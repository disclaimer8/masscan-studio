# rmasscan: нативный Rust, фаза 1 (`rmasscan-core` и `rmasscan-net`) — дизайн

Дата 2026-11-16. Основа: main `fab13114` (после подэтапа баннеров 4b).

## Зачем

Порт писался ради паритета с C masscan `8e6b3b0` и местами сохранил форму C: целые числа вместо типов, флаги как
`u8`-константы, ручные циклы по индексам, копии буферов, сотни `as`, выходные параметры и значения-сторожа. Цель
фазы 1 — сделать `rmasscan-core` и `rmasscan-net` идиоматичным Rust и быстрее, с замерами. Поведение при этом не
меняется. Потом отдельно исправляются выбранные баги C, которые ядро сейчас повторяет.

## Решения пользователя (2026-11-16)

- Цель — и идиоматичный код, и скорость. Каждое ускорение подтверждается замером.
- Начать сейчас, не трогая того, что меняет подэтап 4c (ветка `feat/rmasscan-banners-4c`): `rmasscan-net`
  целиком, `rmasscan-core` кроме `src/config.rs` и `src/stack.rs`. `rmasscan-proto`, `rmasscan-engine`,
  `rmasscan-cli`, `rmasscan-lab` и всё, что меняет публичный API, — фаза 2, после слияния 4c.
- В `rmasscan-net` включены четыре изменения, которые меняют видимое поведение (каждое — своя задача с замером на
  стенде):
  - P1, пакетная отправка `sendmmsg` на Linux. `tx_mode` станет `SendQueue`, статистика пачек будет ненулевой, пауза
    и остановка сработают с точностью до пачки;
  - P2, ожидание события Npcap на Windows вместо опроса раз в 1 мс, когда RX простаивает;
  - P3, настройка TX-сокета Linux: больший `SO_SNDBUF`; `PACKET_QDISC_BYPASS` — только после того, как `ENOBUFS`
    станет повторяемой ошибкой. Начинается с замера частоты `EAGAIN`;
  - P5 (решение 2026-11-16, после диагноза стенда в задаче 1 плана `rmasscan-net`), буфер приёма RX-сокета Linux:
    4 MiB через `SO_RCVBUFFORCE`, без CAP_NET_ADMIN — `SO_RCVBUF` до предела `rmem_max`; отказ не мешает открытию,
    TX-сокет не меняется. С буфером по умолчанию (`rmem_default`, около 208 KiB) пауза потока RX в несколько
    миллисекунд при десятках тысяч ответов в секунду теряет кадры в ядре, и движок обрывает скан (`RxLoss`). Правило
    движка «остановка на первой потере» остаётся (фаза 2).
- Не включены: N8 (перевод старого разбора `GetAdaptersAddresses` на соседний разбор с проверками) и P4 (ленивый
  дедлайн на Linux).
- `rmasscan-net/src/macos/spike.rs` (тестовый код закрытого спайка BPF) удаляется, строка в
  `docs/macos-feth-lab.md` правится. Отчёт спайка в `docs/experiments/` остаётся.
- Баги C, которые ядро сейчас повторяет, исправляются отдельным PR после рефакторинга. Решение «багов не повторять»
  от 2026-11-15 здесь распространяется на уже влитые этапы:

  | # | где | C | что не так |
  |---|---|---|---|
  | B1 | `ranges.rs` (`RangeList::exclude`) | `massip-rangesv4.c:766` | исключение, которое начинается с 0.0.0.0 или 0.0.0.1, целиком снимает цель и заходит на следующую, к следующим целям не применяется: исключённые адреса сканируются |
  | B2 | `ranges.rs` (`range_is_cidr`) | `massip-rangesv4.c:98-101` | `--echo` печатает `0.0.0.0/4294967295` для `0.0.0.0/31`, а прочитать эту строку обратно нельзя |
  | B3 | `arp.rs` (`incoming_request`) | `stack-arpv4.c:70-75` | отвечает на ARP-запрос с неверной длиной одного из полей или с типом оборудования 6 |
  | B4 | `scan.rs` (`list_bounds`) | `main-listscan.c:35` | `-sL --retries N` выводит лишние `N * rate` индексов вместо `N * range` |
  | B5 | `packet.rs` (`Tcp6SynTemplate`) | `templ-pkt.c:1473-1488` | `--ttl` не доходит до IPv6-проб, hop limit всегда 255 |
  | B8 | `payloads.rs` (`parse_c_string`) | `templ-nmap-payloads.c:100-160` | `\8` и `\9` в `--nmap-payloads` дают NUL, а цифра остаётся в строке |
  | B9 | `top_ports.rs` | `main-conf.c:934-1037` | таблица повторяет 465, 554, 3389 и 8080, `--top-ports N` даёт меньше N разных портов |

  Остаются как в C: текст IPv6-адресов (`format_ipv6_c`, сжимается первая нулевая группа, а не самая длинная) — это
  форматирование, а не баг; и три места без видимого эффекта (`checksum_ipv4` для протоколов 0/1/2, минимум
  `throttle` в 0, обрезка `port_them` в cookie IPv6).

## Ограничения (для всех задач фазы 1)

- **Поведение байт в байт.** Кадры на проводе и их порядок, перестановка BlackRock, cookie, контрольные суммы,
  записи, тексты ошибок, которые сверяют тесты, верификаторы стенда и Studio. Исключение — только P1–P3, P5 и
  удаление спайка, решённые выше. Задачи рефакторинга не меняют ни одного эталона (`tests/golden`).
- **Сначала страховка.** До первой правки `src/` фиксируются дайджесты потоков кадров и `-sL` на неизменённом коде
  (`fab13114`). Эталонные копии старых функций (контрольная сумма, раунд BlackRock, сборка SYN) остаются в тестах
  как образцы для дифференциальных проверок. Причина: `tests/probe_cursor.rs` строит ожидаемые кадры теми же
  `transmit_scan` и `build_syn`, которые меняются, и поэтому изменения байтов не заметит.
- **Публичный API заморожен.** Сигнатуры существующих `pub`-элементов не меняются, допустимы только новые элементы.
  4c уже использует `cookie::siphash24`, `syn_cookie_ipv4/ipv6`, параметр окна в `tcp_frame.rs` и поля
  `probe::NicBinding`. Всё, что требует смены сигнатуры, записывается в список фазы 2.
- **Зависимости.** Новых нет, `Cargo.lock` не меняется (запрет на C-тулчейн; criterion отвергнут по этой причине).
  Rust 1.99.1, edition 2024. `unsafe` разрешён только в `rmasscan-net`; новый `unsafe` — только узкими блоками с
  `// SAFETY:`, а общее число блоков в рабочем коде не растёт, кроме P1/P2, где новые блоки названы в задаче.
- **Скорость.**
  - Числа с Mac только ранжируют кандидатов.
  - Ворота для каждой задачи на скорость — прогон 2^28 из `rmasscan/BENCHMARKS.md` на Linux-хосте стенда (CPU
    оракула), дерево из `git archive`: без регрессии, число записывается в `BENCHMARKS.md`.
  - Бенчмарк сначала получает цикл `ProbeCursor` (`preload(64)` + `advance_sent_n`), потому что движок шлёт именно
    через него, а он сейчас на 20–24 % медленнее цикла бенчмарка.
  - Для `rmasscan-net`: новая ячейка без ограничения скорости на Linux-стенде; существующая матрица
    производительности остаётся VALID, потерь RX нет.
- **Три ОС.** CI гоняет тесты на Linux, Windows и macOS. Код только для Linux или только для Windows проверяется на
  Linux-хосте стенда и Windows-госте до приёмки. Тесты, которые сверяют текст `errno`, сверяют вид ошибки, а не
  текст ОС.
- **Studio не меняется.** `cargo check --locked` и `cargo xtask test` в отдельном target-каталоге.
- **Гигиена публичного репозитория.** Ни локальных путей, ни имён пользователей, хостов и LAN-адресов; хосты
  называются по роли.

## Порядок работ

1. Ветка `refactor/rmasscan-native-core`, план `docs/superpowers/plans/2026-11-16-rmasscan-native-core.md`:
   страховка, затем BlackRock (маски раундов, перестановка по 8 индексов с чередованием), `ProbeCursor` (повторное
   использование буферов кадров, конкретный итератор вместо `Box<dyn Iterator>`), сборщики кадров (инкрементальная
   сумма IP, `as_chunks` в `ip_header_checksum`, общий код четырёх шаблонов), однократный вызов SipHash, деления,
   разбор ответов и общие читатели big-endian, `Builder::fill` по видам протоколов, `build_into` для кадров стека,
   мелкие идиомы, разбор конфигурации.
2. Ветка `refactor/rmasscan-native-net`, план `docs/superpowers/plans/2026-11-16-rmasscan-native-net.md`:
   страховка (тесты раскладки ABI, конкурентный тест счётчиков, микробенч адаптера), счётчики TX и RX на разных
   строках кэша, переносимый разбор маршрутов, общие примитивы Unix, FFI macOS и удаление спайка, общие помощники
   бэкендов и `as`, один разбор netlink и переносимый адаптер Linux, пакетный приём `recvmmsg`, чистка Windows
   (N7, N9, N14), затем P1, P2 и P3.
3. Ветка `fix/rmasscan-core-c-bugs` после слияния п. 1: B1–B5, B8, B9. У каждого бага: строка в README со ссылкой на
   C, обновлённый эталон как объявленное отличие, тест на правильное поведение. Если для объявленного отличия нужно
   менять верификаторы `rmasscan-lab`, а 4c ещё не влита, сначала сверяемся с веткой 4c.

Ветки 1 и 2 независимы (разные крейты) и идут параллельно в своих worktree. Push и PR — только с согласия
пользователя.

## Фаза 2 (после 4c, сюда не входит)

Из обзоров:
- адреса как `Ipv4Addr`/`Ipv6Addr` в публичных типах вместо `u32`/`u128` и нулей-сторожей;
- структуры параметров вместо девяти позиционных аргументов в `scan.rs`;
- `PortIndex` вместо смещений `TEMPL_*`;
- арена кадров вместо `Probe.frame: Vec<u8>`;
- заимствующий RX в трейте `Rx` движка (убирает копию кадра на macOS и Windows; без него нет mmap-колец Linux
  `PACKET_TX_RING`/`RX_RING`);
- собственный вариант `TxMode` для пакетной отправки Linux;
- `#[non_exhaustive]` у структур статистики;
- `lookup_many` для маршрутов (до 1024 перечислений интерфейсов в `plan_physical`);
- типизированный `NetError`;
- переиспользование `Vec<&[u8]>` на пачку в TX-цикле движка;
- рефакторинг `rmasscan-proto`, `rmasscan-engine`, `rmasscan-cli`, `rmasscan-lab`.
