# Benchmarks

## Stage 1 exit criterion: offline generation >= 80% of C

Result: **parity, about 0.96-0.99 loop for loop; the >= 80% criterion is met.**
Against the manifest figure (C wall clock, 2,843,897 pps) the Rust median of the
latest measurement is 2,882,526 pps (1.014), but that compares a bare loop with a
whole process, so the loop-for-loop ratio is the honest one (see below).

### Oracle (C masscan)

`tests/golden/manifest.json` -> `offline_gen_pps` = 2,843,897, from
`offline_gen_bench`: 2^28 targets in 94.39 s wall clock (whole process: start, exit and fixed sleeps).

```
masscan 0.0.0.0/4 -p80 --rate 100000000 --offline --interface lo \
  --adapter-ip 10.255.0.1 --adapter-mac 00-11-22-33-44-55 \
  --router-mac 66-55-44-33-22-11 --source-port 40000 --seed 1 --wait 0
```

### Hardware

minipc: Intel Pentium Silver N6005 @ 2.00 GHz, 4 cores, Ubuntu 26.04 (Linux
7.0.0-38, x86_64). Same machine as the oracle. rustc/cargo 1.99.1 installed via
rustup (minimal profile, `--no-modify-path`) under `~/.cargo`.

### Rust measurement

Method: `tests/offline_gen.rs::offline_generation_meets_80pct_of_oracle`
(`#[ignore]`, release only). It builds `0.0.0.0/4`, port 80 (2^28 packets), then
times `generate()` from `tests/common/offline_gen.rs`:

- `Throttler` (`SystemClock`, rate 1e8) driven like main.c:289: `next_batch` when
  the batch is exhausted, one decrement per packet;
- `transmit_scan` (index, BlackRock shuffle with seed 1 / 14 rounds, pick);
- `syn_cookie_ipv4` per packet, then `TcpSynTemplate::build_syn` into a reused `Vec`;
- no send step (offline `rawsock_send_packet` is a no-op).

Timing covers only the generation loop (not process start or target setup).
The C wall clock carries fixed overhead that the Rust figure does not: the 1 s
sleep at `transmit_thread` start (main.c:231), a 100 ms sleep (:1395), the 750 ms
end-of-scan poll (:1440), the 250 ms wait-loop sleep (:1513) and the post-loop
drain of 1000 x `usleep(100)` (:470-492). A two-point fit by the reviewer (2^28
vs 2^24 targets) puts the fixed overhead at 2.3-3.1 s, i.e. 2.4-3.3% of 94 s.
Removing it makes C about 2.91-2.94 M pps loop-only (2^28/(94.39-2.3) = 2,914,925
at the low end), so Rust is at parity.

Commands (from the repo root; the tree is shipped with `git archive`, not
copied from a working tree):

```
git archive HEAD:rmasscan | ssh minipc 'rm -rf ~/rmasscan-bench && mkdir ~/rmasscan-bench && tar -x -C ~/rmasscan-bench'
ssh minipc 'cd ~/rmasscan-bench && ~/.cargo/bin/cargo test --release \
  -p rmasscan-core --test offline_gen -- --ignored --nocapture'
```

The test refuses to run in debug and skips with a message if `/proc/cpuinfo`
reports a CPU different from the manifest's `offline_gen_bench.cpu_model`.

## rmasscan-net: нативный Rust, фаза 1 (Linux-стенд)

Как задачи о скорости плана `docs/superpowers/plans/2026-11-16-rmasscan-native-net.md` доказывают ускорение
`rmasscan-net` и отсутствие регрессий. Числа с Mac (и микробенч `adapter_hot_path_two_threads`) только ранжируют
кандидатов; доказательство дают ячейки `U` стенда S на Linux-хосте стенда (`$LINUX_HOST`: Intel Pentium Silver N6005,
4 ядра, тот же CPU, что у оракула выше), сборка из `git archive` коммитов, как `L-gate`. Существующая матрица 4×5
(`scripts/wire-lab.sh --suite perf`) остаётся 40/40 VALID без потерь RX; стенд S её не заменяет.

### Стенд S

Скрипт ниже (`stand-s.sh`) кладётся на хост в каталог сессии `mktemp -d /tmp/rmasscan-native-net.XXXX` (в
репозиторий не кладётся отдельно: его текст живёт только здесь и берётся отсюда без изменений). Под `sudo -n` он
поднимает изоляцию по правилам `scripts/wire-lab.sh`: две netns `rnn-a` (сканер) и `rnn-b` (пир), пара veth
`rnn-va`/`rnn-vb`, созданная внутри `rnn-a` с концом, сразу перенесённым в `rnn-b`; без uplink, моста и NAT, IPv6
выключен в обеих netns и на обоих концах, `ip_forward` 0, маршрута по умолчанию нет; MAC `02:aa:00:00:00:01` /
`02:aa:00:00:00:02`; сканер `10.200.0.1/24` (адрес адаптера `10.200.0.200` не назначен никому и лежит вне диапазона
пира, у пира на него постоянный сосед, ARP на проводе не нужен); у пира 128 адресов `10.200.0.2-10.200.0.129/24` без
слушателей (ядро пира отвечает RST на каждый SYN); offload контрольных сумм TX выключен на обоих концах (как в `wire-lab.sh`: veth отдаёт
AF_PACKET кадры с незаконченной суммой, движок их отверг бы). Корневая qdisc `rnn-va` — параметр `--qdisc`
(по умолчанию `noqueue`, как в матрице; задача 17 передаёт `tbf` через него, не правя скрипт). Изоляцию проверяет
`rmasscan-lab capture isolation` (режим по умолчанию: только `lo` и veth, не больше одного маршрута без шлюза,
`ip_forward` 0, IPv6 выключен, нет маршрута до 8.8.8.8, список линков хоста не изменился); снятие — trap на выходе
(`ip netns del rnn-a; ip netns del rnn-b`, итог `namespaces_left` в журнале; оставшаяся netns делает сессию
неудачной). Скрипт отказывается стартовать, если `rnn-a`/`rnn-b` уже есть. Каждый прогон сканера идёт под
`taskset -c 2,3` (один набор на сессию, `--cpus`; хотя бы один CPU остаётся вне набора) и `timeout -k 10 <3 × ожидаемая
длительность>`, после тихого окна хоста («Протокол сессии» и «Позиционный эффект стенда» ниже).

Адрес адаптера — `10.200.0.200`, а не `10.200.0.100` из текста плана: `.100` лежит в диапазоне пира, и пир отбрасывал
каждый SYN со своего адреса как martian source (первая сессия ниже). Источник истины для стенда S и ячейки U с этого
момента — этот раздел, а не план.

Сессия целиком запускается с Mac под общим замком стенда (хост делится с планом `rmasscan-native-core`), после сборки
на хосте из `git archive` дерева (`l_ship`, архив `<sha>^{tree}`) нужных sha в каталог сессии `$D`:

```bash
# на хосте, каждый sha в СВОЙ target-каталог на диске хоста (CARGO_TARGET_DIR=~/rnn-target-<sha>, удаляется после
# сессии): wire_scan (release) -> $D/wire_scan-<sha>; один раз rmasscan-lab -> $D/rmasscan-lab; для дымового прогона:
# cargo test --locked --release -p rmasscan-net --test linux_io --no-run -> $D/linux_io-<sha>
"$TO" -k 60 7200 ssh -n "$LINUX_HOST" "sudo -n bash $D/stand-s.sh --out $D/s --lab-bin $D/rmasscan-lab \
  [--smoke $D/linux_io-<sha>] --base $D/wire_scan-<база> [--new $D/wire_scan-<новая> [--distinct]] [--cells tx,rx] \
  [--qdisc noqueue]"
```

Сборки не делят target-каталог. `git archive` коммита ставит всем файлам время коммита, а cargo узнаёт членов
workspace по относительному пути и времени файлов, поэтому в общем каталоге дерево, собранное вторым, молча получало
сборку первого: две сессии `U-TX` задачи 2 сравнивали один и тот же бинарник (ниже), а в задаче 2b `linux_io` нового
коммита совпал байт в байт с базовым. Отсюда три правила (решение контролёра 2026-11-17): `l_ship` архивирует дерево
(время файлов — время распаковки), каждый sha собирается в свой каталог `~/rnn-target-<sha>`, и если деревья базы и
новой различаются (`git diff --quiet <база> <новая> -- rmasscan` не ноль), сессия идёт с `--distinct`: при равных
sha256 двух `wire_scan` скрипт останавливается до первого прогона (сессия INVALID). Хэши бинарников пишутся в
`stand.txt`.
Каталог `$D` создаётся с правами 755 (дымовой прогон запускает тест без привилегий от `nobody`). Итог сессии:
`$D/s/summary.json` (медианы, `S_AA`, `T`, `R_RX`, отношения и вердикты), `$D/s/runs.jsonl` (каждый прогон: метрики,
годность и причины негодности), `$D/s/session.log`, `isolation.json`, `stand.txt`, `smoke-*.log`; сырые JSON
`wire_scan` лежат в `$D/s/runs/` без списка ответов (его выбрасывает `sed`: на `U-RX` это миллионы строк, а
`reply_unique` в JSON остаётся). Извлечь скрипт из этого файла:
`awk '/^<!-- stand-s.sh begin -->$/{f=1;next} /^<!-- stand-s.sh end -->$/{f=0} f' rmasscan/BENCHMARKS.md | sed '1d;$d' >stand-s.sh`.

**Дымовой прогон адаптера** (задачи 1, 6, 13, 15, 17): `--smoke` до ячеек — бинарник `linux_io` из
`cargo test --release --test linux_io --no-run` под `ip netns exec rnn-a env RMASSCAN_LAB_IFACE=rnn-va
RMASSCAN_LAB_IP=10.200.0.200 RMASSCAN_LAB_MAC=02:aa:00:00:00:01 RMASSCAN_LAB_PEER_MAC=02:aa:00:00:00:02 timeout -k 10
600 <bin> --ignored --test-threads=1 --skip lab_open_without_privilege_is_permission_denied lab_`, затем
`lab_open_without_privilege_is_permission_denied` отдельно под `setpriv --reuid=nobody --regid=nogroup
--clear-groups`; каждый лог проходит проверку «каждая строка `running N tests` имеет итог и N ≥ 1», иначе сессия
не годна.

### Ячейка U

`wire_scan` (release) из `ip netns exec rnn-a taskset -c 2,3` с `--iface rnn-va --src-ip 10.200.0.200 --src-mac
02:aa:00:00:00:01 --router-mac 02:aa:00:00:00:02 --seed 1 --source-port 40000 --wait 1`; qdisc `rnn-va` — `noqueue`,
если задача не говорит иначе. CPU потоков движка берётся из `workers.tx_cpu_ns`/`workers.rx_cpu_ns` JSON (первое поле
`/proc/thread-self/schedstat`, прочитанное в `Drop` обёрток harness в потоке движка), а не из CPU всего процесса;
`null` или `0` (учёт выключен) делает прогон INVALID. Перед каждым прогоном — тихое окно хоста (не меньше 5 с;
«Протокол сессии»), а не пауза 1 с, как до задачи 12c.

- `U-TX` — `--rate 100000000 --targets 10.200.0.0/16 --ports 1-64` (4 194 304 пробы; ожидаемая длительность 20 с,
  таймаут 60 с). Метрики: `timing.steady_pps` (больше — лучше); CPU потока TX на отправленный кадр
  `workers.tx_cpu_ns / net.tx_sent`, нс (меньше — лучше; на veth сюда входит и обработка кадра пиром в softirq того
  же CPU); `net.tx_would_block` (меньше — лучше). Годный прогон: код выхода 0, `reason == "Completed"`, `net.tx_sent`
  равен числу проб, прирост RX-пакетов `rnn-vb` по `ip -s -j link` не меньше `net.tx_sent`,
  `rx_health.kernel_drops == 0`, оба `*_cpu_ns` больше нуля. Шумный прогон (CPU вне `--cpus` за время прогона заняты
  больше 5 %) в счёт не идёт: он записывается с причиной `noisy`, а его слот повторяется, если шум — единственная
  причина негодности («Протокол сессии»).
- `U-RX` — измерима с задачи 2b: до P5 не годна ни на одной ступени из-за буфера приёма по умолчанию (диагностика
  ниже, «U-RX: не измеряется на этом стенде»); с P5 (буфер 4 MiB) и старым harness — тоже, из-за предела CPU двух
  закреплённых ядер; с P5 и harness без системного вызова на кадр (`6bc3ee59`) калибровка v3 годна, `R_RX` 300 000
  («U-RX после P5» ниже). Определение ячейки не менялось, кроме двух нижних ступеней лестницы.
  `--targets 10.200.0.2-10.200.0.129 --ports 1-P --rate R_RX`, `P = ⌈11 · R_RX / 128⌉`, `128 · P` проб
  (таймаут `3 × (пробы / R_RX + 4)` с). Метрика: CPU потока RX на принятый кадр `workers.rx_cpu_ns / net.rx_packets`,
  нс (меньше — лучше). Годный прогон: код выхода 0, `reason == "Completed"`, `rx_health.kernel_drops == 0`,
  `reply_unique` не меньше числа проб, оба `*_cpu_ns` больше нуля. `R_RX` выбирается в калибровке сессии: наибольшая
  ступень лестницы 400 000, 300 000, 200 000, 150 000, 100 000, 75 000, 50 000 pps (две нижние — с задачи 2b),
  на которой все прогоны базы годны (на первом
  негодном прогоне ступени скрипт спускается на следующую). Движок обрывает скан на первой потере ядра (`RxLoss`),
  поэтому прогон без ограничения скорости здесь не годен по определению. Для справки (не ворота) после A/B — по одному
  прогону каждой версии на каждой ступени сверху вниз; наибольшая ступень с годным прогоном у каждой версии пишется
  в таблицу. `R_RX` — метка ступени (`--rate`), а не достигнутая скорость: когда отвечает каждая проба, стенд на
  `6bc3ee59` даёт 125–137 тыс. ответов в секунду при `R_RX` 300 000, а ступень 400 000 не прошла по таймауту ячейки
  (`3 × (пробы / R_RX + 4)` считает от метки), не по потерям.

### Протокол сессии, годность и ворота

Одна сессия = один подъём стенда S, без перезапуска хоста, под замком стенда. Хост общий (раннеры CI и сервисы других
проектов; их не останавливают и не перенастраивают), поэтому с задачи 12c перед **каждым** прогоном идёт тихое окно:
CPU вне `--cpus` заняты не больше 5 % за 5 с подряд и load average за минуту ниже 3,0; на слот прогона — не больше
30 минут ожидания, иначе сессия не годна; пока окно ждёт, раз в 60 с в журнал сессии идёт строка-пульс. Прогон
`U-TX`, за время которого CPU вне `--cpus` были заняты больше 5 %, шумный: записывается и в счёт не идёт. Если шум —
единственная причина его негодности, слот повторяется после следующего тихого окна (в пределах тех же 30 минут; слот,
шумный и после них, останавливает сессию как не годную в любой серии: калибровка, A/B, `perf`). Прогон, негодный по
любой другой причине (код выхода, `reason`, потери ядра, число кадров, ответы), не повторяется никогда, даже если он
ещё и шумный: его судят по обычным правилам. Для `U-RX` занятость только записывается (почему — «Позиционный эффект
стенда»).

1. (задачи 1, 6, 13, 15, 17) дымовой прогон адаптера `--smoke`;
2. по каждой ячейке прогон разогрева базой (не идёт в счёт: первый прогон после простоя тратит запас мощности пакета и
   быстрее остальных), затем калибровка «база против базы»: 5 пар одного и того же бинарника базы в порядке ABBA (пара i
   нечётная — `base1`, `base2`; чётная — `base2`, `base1`). По каждой метрике `S_AA = |медиана₁ − медиана₂| / медиана` (медиана₁ — прогонов `base1`,
   медиана₂ — `base2`, медиана — всех десяти; при нулевой медиане `S_AA = 0`), порог `T = max(2 %, S_AA)`;
3. парные A/B (`--new`): 5 пар в той же сессии в порядке ABBA (нечётная пара — база, новая; чётная — новая, база;
   с задачи 2b: при постоянном порядке «база, затем новая» две сессии одинаковых бинарников дали `r` 0,948 и 1,020,
   то есть эффект порядка до ~5 %, которого калибровка не видела); затем справочная лестница `U-RX`;
4. (по решению контролёра, `--perf-stat N`) серия `perf`: ещё N прогонов каждой версии в порядке ABBA под
   `perf stat -x, -e instructions:u,cycles:u`, вне ворот и вне медиан A/B; в `summary.json` — команды и такты
   пространства пользователя на отправленный кадр (медианы и новая/база);
5. C-оракул (`--oracle`) — отдельной серией после A/B, только для справки (время и прирост пакетов пира, не ворота).

База — коммит ветки до первой правки задачи, новая — последний коммит задачи (оба sha в заметках задачи), сборка из
`git archive` этих sha. Негодный прогон — INVALID: никогда не PASS, в медианы не идёт. INVALID базы в калибровке —
сессия не годна (для `U-RX` — шаг вниз по лестнице, для `U-TX` — новая сессия; скрипт останавливается). INVALID новой
версии при годной базе — FAIL задачи. Слот, оставшийся шумным 30 минут, и хост, не затихший за 30 минут, — сессия не
годна (не FAIL новой версии).

Отношение «в сторону лучше» `r`: для `steady_pps` новая/база, для метрик «меньше — лучше» база/новая; равные
значения (в том числе два нуля) дают `r = 1`.

- **Без регрессии** (каждая метрика ячейки): `r` медиан новой и базы из A/B не ниже `1 − T` и не ниже 0,97, какой бы
  ни вышла `S_AA`; и не меньше чем в 4 из 5 пар `r` новой версии к своей паре не ниже `1 − T`.
- **Подтверждающий повтор** (с задачи 12c, решение контролёра). Флаг ставится по метрике, а решение принимается по
  ячейке (`U-TX` или `U-RX`):
  - метрика «без регрессии» не прошла **только** по числу пар, если `r` её медиан не ниже `1 − T` и не ниже 0,97
    (`no_regression_failed_on: "pairs"` и `confirmatory_rerun: true` у метрики в `summary.json`); провал на
    медиане — `"median"`;
  - повтор идёт, только если **ни одна** метрика ячейки не провалилась на медиане (у ячейки в `summary.json`
    `median_failed` пуст и `confirmatory_rerun: true`; в журнале строка «fails only on the pair count: ONE
    confirmatory rerun …»). Если хоть одна метрика ячейки провалилась на медиане, FAIL ячейки окончательный сразу,
    без повтора (строка «… failed on its median: FAIL is final, no rerun»);
  - повтор — всё A/B ячейки один раз: те же бинарники, новая сессия (новый подъём стенда S), те же правила. Он решает
    только метрики «без регрессии», не прошедшие в первой сессии по одному числу пар; его вердикт по ним
    окончательный. Обе сессии пишутся сюда;
  - ворота «ускорение» судятся только по первой сессии, повтор их не меняет;
  - негодная сессия повтора (слот, шумный 30 минут, хост, не затихший за 30 минут, INVALID базы) переделывается по
    обычным правилам годности и остаётся тем же одним повтором;
  - повтор запускает оператор, а не скрипт (одна сессия скрипта — один подъём стенда).

  Причина: на калибровке v4 (ниже) из 504 выборок по 5 пар одинакового кода (10 пар, обе роли) правило «без
  регрессии» по ячейке `U-TX` не проходит в 56 — из-за редких медленных прогонов без признаков шума. В 21 из них
  провал на медиане (окончательный FAIL сразу), в 35 — только по числу пар (повтор); остаточная доля ложного FAIL
  ≈ 4,9 % (21/504 + 35/504 · 56/504). В этом плане FAIL «без регрессии» ведёт к диагностике до любого отката, поэтому
  ложный FAIL стоит сессии, а не ошибочного отката.
- **Ускорение** (целевая метрика задачи): `r` медиан больше `1 + T`, и не меньше 4 из 5 повторов новой версии лучше
  медианы базы — только по первой сессии; прочие метрики — «без регрессии». Если ворота «ускорение» не пройдены, продуктовые коммиты задачи
  отменяются `git revert` (история не переписывается), отрицательный замер с `T` пишется сюда, решение за
  пользователем.

`summary.json` сессии содержит по каждой метрике медианы, мин–макс, `S_AA`, `T`, `r`, число пар и оба вердикта
(`no_regression`, `speedup`); строка таблицы ниже переносит их как есть. С задачи 12c там же проверка позиции
калибровочных пар (`position`: в скольких парах второй по времени прогон хуже первого и медиана второй/первый) и число
шумных прогонов (`noisy_runs`); сессия, где второй прогон хуже в каждой паре, показывает эффект позиции, а не шум.

1. **Потоки TX и RX меняют CPU 2 и 3 от прогона к прогону** — нет. Внутри каждого прогона поток TX сменил CPU 8–18 раз

2. **Турбо и нагрев от предыдущего прогона** — не причина чередования: частота CPU потока TX — 3,2–3,3 ГГц почти во
   всех прогонах, а медленный прогон идёт за быстрым и быстрый за медленным, тогда как перенос нагрева действовал бы в

   защиты, в быстрых — 77–87 °C и 0–2 события. Отдельный эффект — первый прогон сессии после простоя (запас мощности,
   видно в `U-RX`).
3. **Состояние netns пира между прогонами** — нет: каждый прогон `U-TX` даёт пиру одно и то же (`Ip.InReceives`

   после каждого прогона, conntrack пира 0.
4. **Порядок бинарников на диске и в кэше страниц** — нет: в A/B первый прогон пары быстрее и когда первым идёт `a`
   (пары 1, 3, 5), и когда `b` (пары 2, 4).
5. **Другая нагрузка хоста** — да. Сервис другого проекта на хосте запускает headless-браузер раз в ~27–28 с: две
   вспышки по 2–3 с с промежутком ~5 с, каждая занимает до 0,5–0,7 каждого из четырёх CPU и гонит сотни пакетов в
   секунду через сетевую карту хоста (запись нагрузки хоста по процессам раз в секунду, 90 с). Прогон `U-TX` на
   исправленном harness длится 12–14 с, с паузой и разбором — около 14 с, то есть два прогона — один период вспышек:
   вспышка попадает в каждый второй прогон. В медленных прогонах A/B прочие CPU заняты на 0,12–0,19, сетевая карта
   даёт 1 497–1 946 прерываний; в быстрых — 0,015–0,04 и 86–149. По 20 прогонам `U-TX` коэффициент корреляции
   `steady_pps` с занятостью прочих CPU −0,83, с прерываниями сетевой карты −0,84. В калибровке той же сессии прочие
   CPU были заняты во всех прогонах (0,06–0,14), и чередования почти не было. Гипотеза (не проверена): пара вспышек
   приходилась на границу прогонов, и каждый прогон ловил по одной вспышке из пары, а не обе через прогон. У старого
   harness (прогон ~20,5 с, сессия задачи 2b выше) цикл не кратен периоду вспышек, поэтому там чередования не было; у
   сессий ядра другие длительности прогонов.

**Причина:** периодическая внешняя нагрузка хоста (вспышки headless-браузера чужого сервиса с периодом ~28 с), период
которой равен двум циклам прогона `U-TX`. В прогоне со вспышкой поток TX делит CPU, кэш, бюджет мощности и тепла пакета
с чужой работой, и пакет доходит до порога тепловой защиты (~92 °C). Остановить или перенастроить чужой сервис нельзя
(правило хоста), поэтому стенд сам ждёт тишины и не считает шумные прогоны.

#### Исправление (коммит `154064fa`, текст скрипта ниже)

Одинаково для базы и новой версии; продуктовый код и harness не менялись.

- **Тихое окно** перед каждым прогоном вместо паузы 1 с: CPU вне `--cpus` (на стенде 0 и 1; сканер их не занимает)
  заняты не больше 5 % за 5 с подряд, load average за минуту ниже 3,0 (собственные прогоны `U-RX` поднимают его до
  ~2,6); на слот прогона не больше 30 минут, иначе сессия не годна. Окно открывается после конца вспышки, поэтому
  каждый прогон стартует в одной фазе внешней нагрузки, и прогон `U-TX` в 12–14 с помещается в промежуток ~20 с между
  вспышками.
- **Шумный прогон `U-TX`**: если за время прогона CPU вне `--cpus` были заняты больше 5 % (в диагностике у тихих
  прогонов 0,015–0,04, у прогонов со вспышкой 0,12–0,19), прогон записывается в `runs.jsonl` с причиной `noisy`, в счёт
  не идёт, а его слот повторяется после следующего тихого окна. Для `U-RX` правило не действует: прогон в 30–45 с
  длиннее промежутка между вспышками, тихого прогона не бывает; занятость только записывается, а позиционного эффекта
  в `U-RX` диагностика не нашла.
- **Прогон разогрева** базой перед калибровкой каждой ячейки, не идёт в счёт.
- **Записи**: у каждого прогона занятость CPU вне `--cpus` в тихом окне и за прогон, load до и после, секунды
  ожидания, номер попытки, прирост событий тепловой защиты и температура пакета до и после; в `summary.json` —
  проверка позиции калибровочных пар и число шумных прогонов.
- Потоки TX и RX за отдельными CPU не закреплялись: смена CPU потоком TX со скоростью не связана, а закрепление
  поменяло бы ячейку.
- **Правки ревью** (после проверки v4, текст скрипта ниже, sha256 `f8c4ec0b…`; меняют только обработку отказов и
  сводку, путь замера тот же): слот повторяется, только если шум — единственная причина негодности; слот, шумный
  30 минут, останавливает сессию в любой серии (раньше в A/B и `perf` скрипт шёл к следующему слоту); тихое окно пишет
  строку-пульс раз в 60 с ожидания; чтение температуры пакета не может остановить сессию; причина FATAL пишется и в
  `session.log` этой сессии; в `summary.json` — число пар A/B каждой метрики (раньше в строке печаталось число пар
  последней ячейки), флаг подтверждающего повтора у метрики и решение по ячейке (`median_failed`,
  `confirmatory_rerun`; «Протокол сессии»).

#### Правило проверки исправления (записано до проверочной сессии)

Записано и закоммичено до проверочной сессии и после неё не меняется. Исправление — тихое окно перед каждым прогоном,
повтор шумных прогонов `U-TX` и прогон разогрева в тексте `stand-s.sh` ниже (коммит `154064fa`, sha256 извлечённого
скрипта `d83e89a2…`).

- **Сессия проверки:** одна сессия стенда S по этому тексту на Linux-хосте стенда под замком стенда, `--cells tx
  --pairs 10` без `--new`: прогон разогрева и калибровка «база против базы» из 10 пар A/A одного бинарника `wire_scan`
  (дерево `cb36833e`, тот же код, что в диагностике) в порядке ABBA (пара i нечётная — `base1`, `base2`; чётная —
  `base2`, `base1`). Каждый счётный прогон годен по правилам ячейки; если скрипт остановил сессию (негодный прогон
  базы или хост не затих за 30 минут), сессия повторяется, а исправление по ней не оценивается. Шумные прогоны в счёт
  не идут, их слот повторяется — это часть исправления; их число пишется в результат.
- **Статистика:** по каждой метрике `U-TX` (`steady_pps`, CPU TX на кадр, `tx_would_block`) и каждой паре i —
  `q_i` = значение второго по времени счётного прогона пары / значение первого (равные значения, в том числе 0 и 0,
  дают 1); «второй хуже» — `q_i < 1` для `steady_pps` и `q_i > 1` для метрик «меньше — лучше». `T = max(2 %, S_AA)`
  этой же сессии (формула калибровки по её 20 счётным прогонам).
- **Исправление принято**, если по каждой метрике выполнены оба условия: (1) второй прогон хуже первого не больше чем
  в 7 парах из 10; (2) `|медиана(q_i) − 1| ≤ T/2`. Числа берутся из `summary.json` сессии (`position`:
  `second_worse`, `median_second_over_first`; `T`) и сверяются пересчётом из `runs.jsonl`.
- **Иначе** исправление не принято и новые исправления не пробуются: сюда пишется предложение статистики,
  сбалансированной по позиции (по каждому блоку ABBA из пары AB и пары BA — отношение (B₁+B₂)/(A₁+A₂), правило пар на

### U-RX: не измеряется на этом стенде (диагностика, задача 1)

Прогоны формы `U-RX` (адрес адаптера `10.200.0.200`, `taskset -c 2,3`, по одному на вариант, не калибровка) с
временным локальным инструментом harness (метки времени вызовов `recv`/`send` в обёртках `IdRx`/`HarnessTx`, журнал
`health`; вариант «скрыть потери» отдаёт движку `kernel_drops 0`, чтобы скан дошёл до конца, а настоящие числа
пишет в журнал). Инструмент в репозиторий не попал; бинарник собран из `git archive` `6ed758b7`.

- **RX начинает читать раньше первого ответа.** Первый вызов `recv` — через 0,19 мс после старта движка, первый кадр
  принят через 0,30 мс, первая отправка TX завершилась через 0,32 мс (ответ на первый SYN доходит до RX раньше, чем
  `send` возвращается в TX).
- **Потери не только в первом всплеске — эпизоды по всему скану.** Со скрытыми потерями: 100 000 pps — 5 494 из
  1 100 032 за 11,4 с, рост ступенями (111 к 0,25 с, 873 → 2 366 между 1,5 и 1,75 с, …); 200 000 pps — 21 160 из
  2 200 064 (24,9 с вместе с хвостом); 25 000 pps — два эпизода (229 к 2,6 с, 848 к 6,2 с). Первые эпизоды на
  100 000 pps совпадают с паузами потока RX вне `recv` (от возврата кадра до следующего вызова): 4,1, 7,1 и 13,9 мс на
  0,30, 0,59 и 1,50 с; в прогоне без скрытия — одна пауза 3,85 мс на 0,29 с и 196 потерь при поступлении ~100 кадров/мс.
  Остальные эпизоды инструмент не объясняет (долгий вызов `recv` неотличим от простоя, TX шлёт пачками).
- **Буфер приёма.** `SO_RCVBUF` RX-сокета — `rmem_default` 212 992 байта (`ss -0 -m`: `rb212992`); по эпизоду выше в
  него помещается ≈190 кадров RST, то есть ≈2 мс при 100 000 pps и ≈8 мс при 25 000 pps. Поток RX тратит 7–10 мкс CPU
  на кадр. Движок считает любую потерю ядра фатальной (`RxLoss`), поэтому одной паузы в несколько миллисекунд хватает,
  чтобы прогон стал негодным.
- **Поднять буфер только в netns сканера нельзя.** На ядре хоста (7.0.0-38) `net.core.rmem_default` и `rmem_max`
  видны в дочерней netns, но с правами `0444` и значением init netns: запись под root внутри `rnn-a` даёт
  `Operation not permitted`, значение хоста не меняется. Менять глобальный sysctl хоста запрещено (на нём другие
  сервисы); `SO_RCVBUF` в адаптере — изменение продукта вне P1–P3.
- **Почему матрица 4×5 потерь не видит.** Ячейка perf на 100 000 pps сканирует `10.200.0.0/22` × порты `1-300`
  (307 200 проб), а отвечают только 4 адреса пира `10.200.0.2-5`: 1 200 ответов за ~3 с, ≈400 в секунду. У `U-RX`
  отвечает каждая проба: 25 000–200 000 ответов в секунду, в 60–500 раз больше.

Итог: `U-RX` на этом стенде не измеряется и в ворота задач не входит; по решению контролёра RX-доказательство
задачи 13 — микробенч и «без регрессии» матрицы, а наблюдение о буфере приёма по умолчанию уходит пользователю как
вопрос о продукте (здесь не исправляется). Пользователь решил исправить его в фазе 1: P5, задача 2b (ниже).

  100 000 на этом хосте недостижимы, и все прогоны идут примерно с одной скоростью. Поток TX тратит 8,7–11,5 мкс CPU
  на отправленный кадр (с обработкой кадра пиром в softirq того же CPU), поток RX — 7,1–8,8 мкс на принятый: два
  потока движка занимают 1,2–1,4 из двух закреплённых CPU, остальным потокам движка и harness остаётся мало. Буфер
  8 MiB вмещает около 7 500 кадров RST (≈1,1 КБ на кадр, оценка задачи 1), то есть 75–100 мс на этих скоростях:
  потеря значит, что поток RX столько времени подряд не вычитывал очередь или в среднем отставал. Обёртки harness
  `IdRx` и `HarnessTx` (`examples/wire_scan.rs`, до плана) на каждом `recv` и `send` вызывают
  `readlink("/proc/thread-self")`, то есть по системному вызову на кадр в обоих потоках; его доля в CPU на кадр не
  измерялась.

Итог первой попытки: P5 работает (буфер RX поднят с 212 992 до 8 388 608, обрыв `RxLoss` отодвинут с ~0,3 с до
1,7–12,8 с при ступенях от 100 000), но со старым harness предел — CPU двух ядер. По решению контролёра harness
перестал спрашивать ОС об идентификаторе потока на каждом кадре (коммит `6bc3ee59`, ниже), а лестница получила
ступени 75 000 и 50 000.

### Задача 17: TX-сокет Linux (P3, 2026-11-18)

У P3 три подшага: `ENOBUFS` при передаче больше не обрывает скан, TX-сокет просит буфер передачи 4 MiB
(`SO_SNDBUF`), TX-сокет обходит qdisc (`PACKET_QDISC_BYPASS`). Подшаг меняет код, только если стенд
показывает то, что он меняет; выполнимость меряется на `ba5a2955` (ветка до задачи). Стенд S по тексту ниже (sha256
скрипта `f8c4ec0b…`, текст не правился), Linux-хост стенда под замком стенда, ядро 7.0.0-38, `taskset -c 2,3`,
`--cells tx`, ячейка `U-TX`; `wire_scan` собран из `git archive` дерева `ba5a2955` в свой target-каталог (удалён),
sha256 `bd28771b…` (тот же файл, что новая версия задачи 15). Конфигурации задаются параметром `--qdisc`: (а) пара
veth как есть, `noqueue`, как в матрице; (б) `tbf` на `rnn-va` внутри netns `rnn-a` (умирает вместе с ней).

**Метод.** Скрипту вместо `wire_scan` даются две обёртки вокруг одного и того же бинарника (вне репозитория): «plain»
пишет `tc -s qdisc` и `ip -s link` интерфейса `rnn-va` до и после прогона и `ss -0 -m` каждые 0,25 с (`t` — память
кадров в полёте у сокета, `tb` — его буфер передачи); «traced» вдобавок запускает прогон под `perf trace -s` (сводка
системных вызовов по потокам за весь прогон; поток TX — по `workers.tx_tid`). Обёртки работают внутри `ip netns exec
rnn-a taskset -c 2,3`, то есть `perf` и выборка делят CPU сканера, а не CPU 0 и 1, за которыми следит тихое окно.
`perf trace` искажает темп: в (а) медиана `steady_pps` под ним 480 363 против 499 460 без него (A/B той же сессии,
−3,8 %), а в (б1) он меняет исход скана (ниже).

**Параметры `tbf`.** Кадр `U-TX` — 58 байт (байты/кадры `ip -s link`), один кадр в полёте сокет учитывает как 960 байт
(`ss`: `t960`), поэтому буфер передачи по умолчанию (`tb` 212 992, `net.core.wmem_default`) держит ≈ 222 кадра,
≈ 12,9 КБ байт кадров. Очередь qdisc возвращает отправителю `ENOBUFS`, только если её предел в байтах меньше этого;
более глубокая очередь сначала заполняет буфер сокета (EAGAIN, `poll`). Поэтому (б) снят в двух вариантах, оба `tbf
rate 100mbit burst 32kb` (215 517 кадров/с при 58 байтах, ниже ~500 000 сканера): (б1) `limit 8kb` (≈ 141 кадр) и (б2)
`latency 50ms` (предел ≈ 657 КБ).

  кадра отправляет его снова (прирост пакетов пира равен `tx_sent`). Накладные расходы трассировки между вызовами дают

  в полную очередь, `sendmmsg` возвращает `ENOBUFS`, и скан обрывается. Терпимость базы к отбросам qdisc зависит от
  темпа.
- **`SO_SNDBUF` (шаг 3) — не выполним, код не менялся.** В (а) поток TX сделал 0 вызовов `poll` на 1000 кадров во всех

  213 120 ≥ `tb`), но там скорость задаёт шейпер (215 500 кадров/с — скорость `tbf`), и критерий брифа — (а). Для
  справки: `net.core.wmem_max` на хосте стенда 4 194 304, и запрос 4 MiB дал бы здесь `tb` 8 388 608 (ядро режет до
  `wmem_max` и удваивает). Вывод, не замер: на очереди, чей предел лежит между байтами в полёте при старом и при новом
  буфере, больший буфер превращает ожидание (EAGAIN) в отбросы qdisc (`ENOBUFS`).

#!/usr/bin/env bash
# Stand S of the rmasscan-net phase-1 plan (rmasscan/BENCHMARKS.md, «rmasscan-net: нативный Rust, фаза 1 (Linux-стенд)»).
# One session = one bring-up of the stand. Sealed by the rules of scripts/wire-lab.sh: namespaces rnn-a (scanner)
# and rnn-b (peer), one veth pair rnn-va/rnn-vb created inside rnn-a with the peer end moved straight into rnn-b;
# no uplink, bridge, NAT or default route; IPv6 off; ip_forward 0; the seal is checked by `rmasscan-lab capture
# isolation`. Every scanner run is pinned with taskset and bounded by timeout. Root only: sudo -n bash stand-s.sh ...
# The host is shared: before every run the stand waits for a quiet host (the CPUs outside --cpus idle for QUIET_S s,
# 1-minute load below LOAD_MAX; at most QUIET_MAX_S s, else the session is not valid), and a U-TX run during which the
# CPUs outside --cpus were busier than RUN_BUSY_TX is noisy: recorded, never counted, and its slot repeats if noise is
# its only fault (a slot still noisy after QUIET_MAX_S s ends the session as not valid).
#
#   --out DIR      session directory (must not exist): runs.jsonl, runs/, summary.json, isolation.json, smoke-*.log
#   --lab-bin BIN  rmasscan-lab (capture isolation)
#   --cpus SET     taskset CPU set of every scanner run (default 2,3; one set per session; must leave a CPU out)
#   --qdisc SPEC   root qdisc of rnn-va: noqueue (default, as the matrix) or a tc spec ("tbf rate 1gbit burst 64kb latency 50ms")
#   --smoke BIN    adapter smoke run first: the linux_io test binary, lab_* as root, then the unprivileged test as nobody
#   --base BIN     wire_scan of the base commit: one warm-up run (never counted), then calibration "base vs base" of
#                  each cell (U-RX: picks R_RX)
#   --new BIN      wire_scan of the task commit: paired A/B after the calibration, then the U-RX reference ladder
#   --cells LIST   tx,rx (default), tx or rx
#   --pairs N      pairs per series (default 5); pair i runs in ABBA order: odd i base-first, even i new-first
#   --distinct     base and new come from different trees: equal sha256 of the two binaries = FATAL (stale build)
#   --perf-stat N  after A/B: N more runs of each version (ABBA, series "perf", never in the gate statistics) under
#                  perf stat -x, -e instructions:u,cycles:u; summary: user-space instructions and cycles per sent frame
#   --oracle BIN   C masscan: one reference series per cell after A/B (never a gate)
set -euo pipefail
export LC_ALL=C

OUT=""; LAB_BIN=""; CPUS=2,3; QDISC=noqueue; SMOKE=""; BASE=""; NEW=""; CELLS=tx,rx; PAIRS=5; ORACLE=""; DISTINCT=0; PERFSTAT=0
while [ $# -gt 0 ]; do
  case "$1" in
    --out) OUT=$2; shift 2 ;;
    --lab-bin) LAB_BIN=$2; shift 2 ;;
    --cpus) CPUS=$2; shift 2 ;;
    --qdisc) QDISC=$2; shift 2 ;;
    --smoke) SMOKE=$2; shift 2 ;;
    --base) BASE=$2; shift 2 ;;
    --new) NEW=$2; shift 2 ;;
    --cells) CELLS=$2; shift 2 ;;
    --pairs) PAIRS=$2; shift 2 ;;
    --oracle) ORACLE=$2; shift 2 ;;
    --distinct) DISTINCT=1; shift ;;
    --perf-stat) PERFSTAT=$2; shift 2 ;;
    *) echo "unknown argument: $1" >&2; exit 64 ;;
  esac
done
FATAL_LOG=""   # this session's session.log once it created --out (never the log of an earlier session)
fatal() { echo "FATAL: $*" >&2; [ -z "$FATAL_LOG" ] || { echo "[stand-s] FATAL: $*" >>"$FATAL_LOG"; } 2>/dev/null || true; exit 2; }
[ "$(uname -s)" = Linux ] || fatal "Linux only"
[ "$(id -u)" = 0 ] || fatal "run as root (sudo -n bash $0 ...)"
[ -n "$OUT" ] && [ -x "$LAB_BIN" ] || fatal "--out and an executable --lab-bin are required"
[ ! -e "$OUT" ] || fatal "$OUT exists: every session gets a new --out"
[ -n "$NEW" ] && [ -z "$BASE" ] && fatal "--new needs --base"
for b in "$SMOKE" "$BASE" "$NEW" "$ORACLE"; do [ -z "$b" ] || [ -x "$b" ] || fatal "not executable: $b"; done

  [ -n "$NEW" ] || fatal "--perf-stat needs --new"

rx_ports() { echo $(( (11 * $1 + 127) / 128 )); }   # P = ceil(11 * R_RX / 128): >= 10 s steady plus the ramp

LOAD_MAX=3.0       # the 1-minute load average before a run is below this (own U-RX runs reach ~2.6)
QUIET_S=5          # quiet window: the CPUs outside --cpus, measured over QUIET_S seconds ...
QUIET_BUSY=0.05    # ... are at most this busy (fraction of their time) right before a run
QUIET_MAX_S=1800   # waiting and noisy repeats of one run slot end after 30 min: the session is not valid
QUIET_BEAT_S=60    # while it waits, the quiet window logs a heartbeat line this often
RUN_BUSY_TX=0.05   # U-TX: a run during which the CPUs outside --cpus were busier than this is noisy and repeats
OTHER_CPUS=$(python3 -c 'import sys
want = set()
for part in sys.argv[1].split(","):
    a, _, b = part.partition("-"); want.update(range(int(a), int(b or a) + 1))
print(",".join(str(c) for c in range(int(sys.argv[2])) if c not in want))' "$CPUS" "$(nproc --all)")
[ -n "$OTHER_CPUS" ] || fatal "--cpus $CPUS leaves no CPU out: the quiet window watches the CPUs the scanner does not use"
other_ticks() {  # "busy total" jiffies of the CPUs outside --cpus (busy = all but idle and iowait)
  awk -v set=",$OTHER_CPUS," '/^cpu[0-9]/ { c = substr($1, 4); if (index(set, "," c ",")) {
    t += $2 + $3 + $4 + $5 + $6 + $7 + $8 + $9; i += $5 + $6 } } END { print t - i, t }' /proc/stat
}
busy_of() { awk -v a="$1" -v b="$2" 'BEGIN { split(a, x, " "); split(b, y, " "); t = y[2] - x[2]; printf "%.4f\n", (t > 0 ? (y[1] - x[1]) / t : 0) }'; }
load1() { cut -d' ' -f1 /proc/loadavg; }
pkg_throttle() { cat /sys/devices/system/cpu/cpu0/thermal_throttle/package_throttle_count 2>/dev/null || echo -1; }
pkg_temp() { local z; for z in /sys/class/thermal/thermal_zone*; do
  [ "$(cat "$z/type" 2>/dev/null)" = x86_pkg_temp ] && { cat "$z/temp" 2>/dev/null || echo -1; return 0; }; done; echo -1; }
quiet_wait() {  # quiet_wait SLOT_START : prints "busy load waited_s" of the quiet window; non-zero once SLOT_START + QUIET_MAX_S passed;
                # a heartbeat goes to stderr and session.log every QUIET_BEAT_S s of waiting (stdout is the caller's capture)
  local a b f l w0=$SECONDS beat=$SECONDS
  while :; do
    a=$(other_ticks); sleep "$QUIET_S"; b=$(other_ticks); f=$(busy_of "$a" "$b"); l=$(load1)
    awk -v f="$f" -v l="$l" -v m="$QUIET_BUSY" -v lm="$LOAD_MAX" 'BEGIN { exit !(f ~ /^[0-9.]+$/ && l ~ /^[0-9.]+$/ && f <= m && l < lm) }' && { echo "$f $l $((SECONDS - w0))"; return 0; }
    [ $((SECONDS - $1)) -lt "$QUIET_MAX_S" ] || { echo "$f $l $((SECONDS - w0))"; return 1; }
    if [ $((SECONDS - beat)) -ge "$QUIET_BEAT_S" ]; then
      beat=$SECONDS
      echo "[stand-s] quiet window: waiting $((SECONDS - w0))s (slot $((SECONDS - $1))s of ${QUIET_MAX_S}s): CPUs $OTHER_CPUS busy $f, load1 $l" \
        | tee -a "$OUT/session.log" >&2
    fi
  done
}

import json, sys
(path, cell, version, series, pair, rate, probes, rc, delta, secs, attempt, quiet, run_busy, load1_after, throttle,
 temp0, temp1, run_busy_tx, sink) = sys.argv[1:]
def num(x, kind=int):  # host readings (throttle count, temperature) are records, never a reason for the judge to fail
    try:
        return kind(x)
    except ValueError:
        return -1
rec = {"cell": cell, "version": version, "series": series, "pair": int(pair), "rate": int(rate),
       "probes": int(probes), "rc": int(rc), "vb_rx_delta": int(delta), "seconds": float(secs),

       "pkg_throttle": num(throttle), "pkg_temp_c": [num(temp0) / 1000, num(temp1) / 1000]}

    why.append(f"noisy: CPUs outside the scanner set {rec['other_busy']:.3f} busy > {run_busy_tx}")
    rec["noisy"] = True
if rec["rc"] in (124, 137):
    why.append("timeout")

    net, w = j["net"], j["workers"]
    rec.update(reason=j["reason"], tx_sent=net["tx_sent"], rx_packets=net["rx_packets"],

except Exception as e:  # no JSON, a failure JSON or a missing field: never a valid run
    why.append(f"no summary JSON ({type(e).__name__}: {e})")
    j = None
if j is not None and version != "oracle":
    if rec["reason"] != "Completed": why.append(f"reason {rec['reason']}")

run_u() {  # run_u CELL VERSION SERIES PAIR BIN RATE : one run slot of cell U (a U-TX run whose only fault is noise repeats)
  local cell=$1 version=$2 series=$3 pair=$4 bin=$5 rate=$6 targets ports probes expect f rc v0 v1 t0 t1 pre slot=$SECONDS attempt=0
  local q o0 o1 th0 th1 tp0 tp1
  if [ "$cell" = tx ]; then targets=$TX_TARGETS; ports=$TX_PORTS; probes=$TX_PROBES; expect=$TX_EXPECT
  else ports=1-$(rx_ports "$rate"); targets=$RX_TARGETS; probes=$((128 * $(rx_ports "$rate"))); expect=$(( probes / rate + 4 )); fi
  while :; do
  attempt=$((attempt + 1)); rc=0; pre=()
  IDX=$((IDX + 1)); f="$OUT/runs/$(printf %03d "$IDX")-$cell-$series-$version-$rate.json"
  [ "$series" = perf ] && pre=(perf stat -x, -e instructions:u,cycles:u -o "$f.perf" --)
  # the quiet window (>= QUIET_S s) also lets the previous run's tail (replies, backlog) end before the next starts
  q=$(quiet_wait "$slot") || fatal "host not quiet for ${QUIET_MAX_S}s before a run (CPUs $OTHER_CPUS busy, load1, waited: $q): the session is not valid"
  th0=$(pkg_throttle); tp0=$(pkg_temp); o0=$(other_ticks)
  v0=$(vb_rx); t0=$(date +%s.%N)
  if [ "$version" = oracle ]; then
    timeout -k 10 $((3 * expect)) ip netns exec "$NS_A" taskset -c "$CPUS" "$bin" "$targets" -p"$ports" \
      --rate "$rate" --interface "$IF_A" --adapter-ip "$IP_ADAPTER" --adapter-mac "$MAC_A" \
      --router-mac "$MAC_B" --source-port 40000 --seed 1 --wait 1 >"$f.out" 2>"$f.err" || rc=$?
    printf '{"reason":"oracle","net":{"tx_sent":null,"rx_packets":null,"tx_would_block":null},"rx_health":{"kernel_drops":null},"reply_unique":null,"timing":{"steady_pps":null},"workers":{}}\n' >"$f"
  else
    timeout -k 10 $((3 * expect)) ip netns exec "$NS_A" taskset -c "$CPUS" "${pre[@]}" "$bin" "${SCAN[@]}" \
      --rate "$rate" --targets "$targets" --ports "$ports" 2>"$f.err" \
      | sed -E 's/"replies":\[[^]]*\]/"replies":"(dropped by stand-s)"/' >"$f" || rc=${PIPESTATUS[0]}
  fi
  t1=$(date +%s.%N); v1=$(vb_rx); o1=$(other_ticks); th1=$(pkg_throttle); tp1=$(pkg_temp)
  judge "$f" "$cell" "$version" "$series" "$pair" "$rate" "$probes" "$rc" "$((v1 - v0))" "$(python3 -c "print(round($t1 - $t0, 3))")" \
    "$attempt" "$q" "$(busy_of "$o0" "$o1")" "$(load1)" "$((th1 - th0))" "$tp0" "$tp1" | tee -a "$OUT/session.log"
  [ "$(repeat_of)" = 1 ] && [ "$series" != warmup ] || break
  [ $((SECONDS - slot)) -lt "$QUIET_MAX_S" ] \
    || fatal "$cell $series $version pair $pair: the run slot stayed noisy for ${QUIET_MAX_S}s: the session is not valid"
  log "noisy run: the slot repeats after the next quiet window"
  done
}
