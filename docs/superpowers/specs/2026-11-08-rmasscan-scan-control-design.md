> Каркас сгенерирован Claude. Разделы с пометкой **ЗАПОЛНИТЬ:** содержат чувствительную
> техническую начинку (точные ссылки `~/masscan/src` файл:строка, байты шаблонов, формулы
> индексов, формат `paused.conf`, последовательность resume) — их вписывает Denys. Остальное
> (структура, цели/не-цели, границы) можно править свободно.

**Статус:** черновик. Исходник C: `~/masscan/src`, HEAD `8e6b3b0` (read-only). Текущая спека порта:
`docs/superpowers/specs/2026-10-23-masscan-rust-port-design.md` (§3 карта подсистем, §4 инварианты, §9 дорожная карта).

## 1. Намерение

Довести ядро rmasscan до поведенческого паритета с masscan по управлению сканом: повторные попытки,
шардирование, пауза/возобновление, фаза ожидания ответов, бесконечный режим и смежные параметры — чтобы
реальные крупные сканы на запечатанных стендах шли как у C. Бан�еры и собственный TCP-стек — отдельный
последующий этап, не здесь.

## 2. Цели, не-цели, анти-цели

**Цели (инвентарь этапа, roadmap-уровень):**
- `--retries N` — повтор зондов.
- `--shards X/Y` — разбиение пространства индексов между экземплярами.
- `--resume` + запись `paused.conf`; фаза ожидания ответов после Ctrl-C (расширение Р18 предыдущего этапа до
  полноценной паузы с дампом прогресса).
- `--infinite`.
- Два порта источника по умолчанию, как в C (сейчас один).
- Несколько адаптеров / следующих хопов (сейчас один).
- `-c`/`--conf` — файл конфигурации.
- Запись `--pcap`.
- `--ttl`, `--badsum`.
- Опции TCP: `--tcp-mss`, `--tcp-wscale`, `--tcp-sackok` и прочее из `templ-tcp-hdr.c`.

**Не-цели:** баннеры и TCP-стек (следующий этап); UDP/SCTP/ICMP/ARP-скан и IPv6 (свои этапы); физические NIC.

**Анти-цели (что делает этап провальным даже при зелёных тестах):**
- ЗАПОЛНИТЬ: какие расхождения с C недопустимы (например: resume теряет/дублирует цели; shards пропускает
  или перекрывает диапазон; retries ломает порядок/формулу индексов).

- Р2: ЗАПОЛНИТЬ (shards: как делится пространство индексов X/Y; формула; взаимодействие с BlackRock).
- Р3: ЗАПОЛНИТЬ (retries: удлинение конца диапазона; защита от незавершающегося shuffle — ср. §4(d) спеки порта).
- Р4: ЗАПОЛНИТЬ (фаза ожидания после Ctrl-C: сколько ждём, что пишем, когда дампим `paused.conf`).

## 5. Как устроено (на уровне швов, без чувствительной начинки)

- Генератор целей/индексов живёт в `rmasscan-core` (shards/retries — чистая логика, без I/O; тестируется офлайн).
- Пауза/resume — состояние движка `rmasscan-engine` + сериализация в `rmasscan-cli` (чтение/запись файла).
- Разбор новых флагов — `rmasscan-cli/src/args.rs`; значения уходят в `core::config`.
- `#![forbid(unsafe_code)]` везде, кроме `rmasscan-net`. Без новых крейтов. Pinned Rust 1.99.1.

## 6. Проверка

- 6.1 Офлайн-паритет с C (CI, три ОС): ЗАПОЛНИТЬ какие сравнения с golden/оракулом (например: `--echo` дампит новые
  параметры; `paused.conf` round-trip; индексы shards/retries против оракула).
- 6.2 Живой паритет (Linux netns, minipc; Windows VM): ЗАПОЛНИТЬ сценарии (например: shard 1/2 + 2/2 покрывают всё;
  Ctrl-C → `paused.conf` → `--resume` досылает ровно остаток; retries досылают N раз).
- 6.3 Регрессия предыдущих этапов (autodetect + output) — без изменений.
- 6.4 GO этапа: ЗАПОЛНИТЬ критерий (офлайн зелёный на трёх ОС; живой паритет Linux/Windows PASS; итоговое ревью; CI на точном HEAD).
