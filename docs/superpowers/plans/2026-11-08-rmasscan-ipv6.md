# rmasscan: IPv6 — план реализации (КАРКАС, заполняет Denys)

> **ОБЯЗАТЕЛЬНЫЙ САБ-СКИЛЛ:** superpowers:subagent-driven-development. Шаги в чекбоксах.
> Каркас от Claude: структура/границы/карта файлов/скелеты TDD на месте; строки **ЗАПОЛНИТЬ:** (ссылки
> `~/masscan/src` файл:строка, байты шаблонов IPv6/NDP, индексация, вызовы ОС, значения тестов) вписывает Denys.
> До заполнения не исполняется.

**Goal:** паритет rmasscan с masscan по IPv6: разбор целей, TCP SYN поверх IPv6, NDP, автоопределение source v6,
индексация v4+v6 без смены порядка v4, записи 10/11 в выводе/`--readscan`.

**Architecture:** разбор/шаблон v6 — `rmasscan-core`; NDP+source v6 — `rmasscan-net` (единственный `unsafe`-крейт);
рендер — существующий `rmasscan-cli::output`.

**Tech Stack:** Rust 1.99.1, workspace `rmasscan/`, без новых крейтов.

**Spec:** `docs/superpowers/specs/2026-11-08-rmasscan-ipv6-design.md`

## Global Constraints

- `#![forbid(unsafe_code)]` кроме `rmasscan-net` (любой `unsafe` под `// SAFETY:`); ноль новых зависимостей;
  `Cargo.lock`/`deny.toml` без изменений; language-guard зелёный; ноль живого трафика/NIC в тестах; приватность репо.
- Сборки/тесты на ноутбуке (Linux); **Windows/macOS ловит только GitHub CI**.
- TDD: красный → реализация со ссылкой на C файл:строка → зелёный.
- Порядок зондов v4 из прошлых этапов НЕ меняется (явный регресс-тест).
