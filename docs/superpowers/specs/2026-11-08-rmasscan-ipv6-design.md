# rmasscan: IPv6 — дизайн (КАРКАС, заполняет Denys)

> Каркас от Claude. Строки **ЗАПОЛНИТЬ:** — чувствительная начинка (ссылки `~/masscan/src` файл:строка, байты
> шаблонов IPv6/NDP, индексация IPv6 в transmit, определение адреса источника на трёх ОС, записи типов 10/11) —
> вписывает Denys. Структуру/границы можно править.

**Статус:** черновик. Исходник C: `~/masscan/src`, HEAD `8e6b3b0` (read-only). Опоры: спека порта §3/§4 (там IPv6
помечен «отложить», индексация transmit учитывает низкие индексы IPv6), спека форматов (записи 10/11 в `--readscan`).

## 1. Намерение

Добавить IPv6 к живому скану (TCP SYN поверх IPv6), с автоопределением адреса источника и шлюза (NDP), с паритетом
на запечатанном стенде, и провести записи IPv6 через форматы вывода/`--readscan`.

## 2. Цели, не-цели, анти-цели

**Цели (roadmap-уровень):**
- Разбор диапазонов/целей IPv6 (`massip-rangesv6.c`).
- Шаблон TCP SYN поверх IPv6.
- NDP: резолв MAC шлюза/соседа (аналог ARP для v6).
- Автоопределение адреса источника IPv6 на Linux/macOS/Windows (аналог текущего v4-автоопределения).
- Индексация IPv6 в transmit-формуле так, чтобы не ломать существующий порядок v4 (спека порта §3 это закладывала).
- Записи типа 10/11 в `--readscan` и рендер IPv6-адресов во всех форматах.

**Не-цели:** баннеры/TCP-стек; физические NIC; туннельные/DHCPv6-сценарии.

**Анти-цели:** ЗАПОЛНИТЬ (например: смена порядка/индексов v4 при добавлении v6; неверный чек-сумма/псевдозаголовок
IPv6; запись 10/11, которую C `--readscan` не читает).

## 5. Как устроено (на уровне швов)

- Разбор целей и шаблон IPv6 — `rmasscan-core` (офлайн-тесты на разбор/байты).
- NDP и source-IPv6 — `rmasscan-net` (единственный крейт с `unsafe`, под `// SAFETY:`), по образцу v4-автоопределения.
- Рендер IPv6-адресов в записях — существующий `rmasscan-cli::output` (расширить `Record` на адрес v6).
- `#![forbid(unsafe_code)]` кроме `rmasscan-net`; без новых крейтов; Rust 1.99.1.
