# Studio: обрыв тестовой сети, частичные результаты и восстановление

Дата: 2026-11-11. Ветка: `integration/studio-current-engine`.
Сетевые проверки выполнены на runner из чистого release-пакета
`de7ee4ad382f55012e2d72ca27bc2e59a13e1e8f`.
Обычный пользователь запускал актуальный Controller через xtask того же исходного
кода; отдельно привилегированный supervisor контролировал стенд и захваты.
GUI этого release-пакета затем открыл сохранённую историю и экспортировал JSON.

Оба независимых offline lifecycle verifier завершились успешно. Их результат
проверяет согласованность материалов; происхождение захватов подтверждается
наблюдавшимся запуском защищённого supervisor через retained work-session,
точными хешами исполняемых файлов и неизменёнными root-owned оригиналами.

Peer-захваты содержат соответственно 20 и 250 Ethernet-пакетов: кроме TCP-проб
и ответов в них присутствуют ARP и завершающие TCP-пакеты. Обе записи uplink
содержат только 24-байтовый заголовок pcap, без пакетов, попавших под фильтр.
Счётчики received на uplink равны 4139 и 11578 — это не утверждение об отсутствии
другого трафика на интерфейсе. Kernel/interface drops равны нулю. Все шесть
процессов захвата и ответчика завершились с кодом 0, без принудительного убийства.
Хеши файлов совпали с манифестами; обе SQLite-истории прошли integrity_check.

Privacy-scan полного complete-захвата выявил один пакет Bonjour/mDNS с именами
устройств. Такой пакет допустим для сетевого verifier как фоновый трафик macOS,
но не подходит для распространяемых материалов. Неизменённые полный захват,
его исходный tar и журнал найденного совпадения перенесены в нейтральный каталог
`/private/var/tmp/studio-fault-private-20261111/` с правами 0700. Root-owned
оригиналы также сохранены. В открытом наборе осталась сводка и манифест без pcap.
Фильтр захвата не сужался: полный трафик нужен для обнаружения неожиданных
пакетов. Согласованность исходного захвата и возможность его публикации — разные
проверки; первая прошла, вторую исходный complete-захват не прошёл.

После проверок точные принадлежащие стенду интерфейсы и маршрут удалены штатным
ownership-checked teardown. Default uplink остался en0. Исходные хеши выбранных
tool/runner возвращены в прежний work-session; тот же PID, 0 активных клиентов.

## Исправление текста GUI

При повторе настроек обнаружена устаревшая подсказка MacNetwork: она ошибочно
описывала всю сборку как ограниченную локальным стендом. Теперь ограничение
явно относится к выбранному профилю, а для разрешённых устройств предлагается
существующий профиль `Mac network · Wi-Fi / Ethernet`.

Изменена одна строка в `network_ui.rs`; scanner, helper, протокол и разрешения
не изменены. `cargo test --locked -p studio-ui`: **55 passed, 0 failed**;
форматирование прошло. Тестовый debug-пакет прошёл inventory, подписи и проверку
пригодности GUI/helper. Исправленная подсказка подтверждена через CUA в его окне.
Полный suite из 484 тестов относится к предыдущему release-пакету и в этом
проходе повторно не запускался. Debug-пакет имеет dirty provenance из-за этой
единственной правки; сетевые результаты выше относятся к неизменённому release.
Его прежний ZIP не заменялся новым debug-пакетом.

## Границы проверки

Это нативная проверка изолированного MacNetwork-стенда с его специальными
проверками целостности. Она не закрывает routed/partial-neighbour acceptance
обычного MacPhysical-профиля, физическую потерю Wi-Fi, смену VPN/маршрута или
sleep/wake. Эти пункты остаются открытыми. Чистая установка, отказ в системной
авторизации, обновление и notarization также не проверялись.

Save выполнен через accessibility setValue для пути и имени, затем обычной
кнопкой Save. Это не новая проверка автоматического посимвольного ввода.
Windows GUI/UAC по указанию пользователя не выполнялись. Ветка Claude,
публичные ветки и релизы не изменялись; merge/push не выполнялись.
