# rmasscan: управление сканом — проектный документ

**Статус:** проект для плана реализации. Исходник C: `~/masscan/src`, HEAD `8e6b3b0` (read-only). Опоры:
[спека порта](2026-10-23-masscan-rust-port-design.md) (§3 карта подсистем, §4 инварианты, §9 дорожная карта),
[спека форматов вывода](2026-11-06-rmasscan-output-formats-design.md) (Р1–Р19).

## 1. Намерение

Довести ядро, движок и CLI `rmasscan` до поведенческого паритета с `masscan` по управлению сканом: повторные попытки,
шардирование, пауза/возобновление через `paused.conf`, полноценная фаза ожидания ответов после Ctrl-C, бесконечный
режим, конфигурационные файлы, несколько адаптеров, захват `--pcap` и параметры зонда (`--ttl`, `--badsum`,
TCP-опции) — чтобы реальные крупные сканы на запечатанных стендах шли и управлялись как у C. Баннеры и собственный
пользовательский TCP-стек — отдельный последующий этап, не здесь.

## 2. Цели, не-цели, анти-цели

**Цели (инвентарь этапа, roadmap-уровень):**
- `--retries N` (`--retry`, `--max-retries`, `--max-retry`) — повтор зондов в живом скане и `--offline --packet-trace`.
- `--shard X/Y` (`--shards`) — разбиение пространства индексов между экземплярами без пропусков и перекрытий.
- `--resume <file>` + запись `paused.conf`; полноценная фаза ожидания поздних ответов (`--wait <secs|forever>`) после
  первого Ctrl-C (расширение Р18 этапа форматов до паузы с сохранением прогресса).
- `--infinite` — непрерывный проход с инкрементом `seed` и сохранением `entropy` для приёма in-flight ответов.
- Диапазоны портов и адресов источника степени двойки (`--source-port A-B`, `--adapter-ip A-B`) и зафиксированное
  решение по эфемерному порту по умолчанию (см. Р6).
- Несколько адаптеров / следующих хопов (`--adapter[0..7]` и сопутствующие ключи с индексом `[i]`, сейчас один).
- `-c` / `--conf` / `--config` и `-iL` / `--includefile` — чтение файлов конфигурации и списков целей.
- `--pcap <file>` (`--pcap-filename`) — сохранение принятых пакетов в классический `.pcap`.
- `--ttl <1..=255>`, `--badsum`, `--noreset`.
- Опции TCP SYN-заголовка из `templ-tcp-hdr.c`: `--tcp-mss`, `--tcp-sackok`, `--tcp-wscale`, `--tcp-tsecho`.

**Не-цели:** баннеры и пользовательский TCP-стек (следующий этап); UDP/SCTP/ICMP/ARP-скан и IPv6 (свои этапы);
физические NIC; авточтение `/etc/masscan/masscan.conf` (запрещено спекой порта §4.6).

**Анти-цели (что делает этап провальным даже при зелёных тестах):**
- Потеря или дублирование неотправленных внешних индексов `i` при цикле Ctrl-C → `paused.conf` → `--resume` (в том
  числе при `retries > 0`, `shard.of > 1` или `nic_count > 1`, если курсор считает отправленные кадры вместо внешнего
  индекса `i`).
- Пропуск или перекрытие целей между шардами `1/Y..Y/Y` или между потоками `nic[0..K)`.
- Расхождение формулы `(i + r * rate) % range` в передаче при `--retries` с `main.c:328–334` или зависание `-sL` на
  вырожденных параметрах BlackRock (спека порта §4(d)).
- Потеря подвала файла вывода (`-oJ`, `-oX`, `-oB`) при первом Ctrl-C либо зависание фазы `--wait` при `--nostatus`
  (баг C `main.c:1399, 1530`).
- Поломка замороженного контракта `Studio` (`AdapterBinding` по литералу из 6 полей в `studio-protocol/src/lib.rs:147`
  и байтов `canonical_job_bytes` в `rmasscan-engine/src/identity.rs` для дефолтных v1-заданий).
- Новые зависимости в `Cargo.lock`/`deny.toml` или файлы вне Rust/docs (`language-guard`).

## 3. Решения автора (Р-номера)

> Каждое решение, где `rmasscan` сознательно расходится с C, переносится в `rmasscan/README.md` («Отличия от masscan»)
> на шаге документации.

- **Р1 (`paused.conf` и `--resume`):** при остановке скана первым Ctrl-C до исчерпания внешнего предела передачи
  (`min_index < effective_end`) записываем `./paused.conf`, печатая в `stderr` затирку из 70 пробелов + `\r` и строку
  `saving resume file to: paused.conf\n` (`main-conf.c:395–416`, `main.c:1447–1452`). Порядок секций повторяет
  `masscan_echo(..., is_echo_all=0)` (`main-conf.c:3636–3780`): `\n# resume information\nresume-index = <u64>\n`,
  `resume-count = <u64>\n` (если задан), `seed`, `rate`, `shard`, `retries`, `noreset` (после `retries`, по порядку
  таблицы `config_parameters[]`, `main-conf.c:2380`), `pcap-filename` (если задан),
  `ndjson-status = true` (если включён), двойной `nocapture = servername\n` + `\n`, секция вывода (`output-filename`,
  `output-format`, `output-append`, `output-flush`, `stylesheet`) + `\n`, изменённые TCP/IP-параметры (`ttl`,
  `badsum`, `tcp-mss`, `tcp-sackok`, `tcp-wscale`, `tcp-tsecho`), секция адаптеров (`masscan_echo_nic`,
  `main-conf.c:294–389`: `adapter`, `adapter-ip`, `adapter-mac`, `router-ip`, `router-mac-ipv4`, `router-mac-ipv6`,
  с суффиксом `[i]` при `nic_count > 1`), `adapter-port` и `# TARGET SELECTION (IP, PORTS, EXCLUDES)\n` с `ports = ...`
  и уже вычтенными `range = ...`. Флаг `--resume <file>` разбирает файл в своей позиции `argv` (ключи правее в `argv`
  переопределяют файл) и принудительно выставляет `output-append = true` (`main-conf.c:2926–2928`); повторный Ctrl-C
  перезаписывает `./paused.conf` — паритет с конвейерами паузы/продолжения C — отличие от C: ошибка чтения `--resume`
  или записи `paused.conf` завершает процесс с кодом `1` вместо молчаливого продолжения (`main-conf.c:401–405,
  3889–3900`), а `paused.conf` сохраняется и на хвостовом участке повторов (`range <= min_index < effective_end`), где
  C терял недосланные ретраи (`main.c:1447`).
- **Р2 (`--shard`/`--shards` и массив адаптеров `nic[0..8)`):** разблокируем в runtime проверку `--shard X/Y`
  (`1 <= X <= Y`, `main-conf.c:2059–2090`) и поддерживаем до 8 интерфейсов с индексным синтаксисом C (`--adapter[i]`,
  `--adapter-ip[i]`, `--adapter-mac[i]`, `--router-ip[i]`, `--router-mac[i]`, `--source-port[i]`, `0 <= i < 8`,
  `main-conf.c:882–890, 2437–2641`). Каждый поток `(shard, nic_index)` идёт по внешним индексам `i` с началом
  `start = resume_index + (shard.one - 1) * nic_count + nic_index` и шагом `increment = shard.of * nic_count`
  (`main.c:223, 269`), скоростью `max_rate / nic_count` (`main.c:249`), общим `DedupCache`/`Sink`, а `resume-index` при паузе равен
  `min_k ProbeCursor::resume_base()` = `min_k( my_index[k] − ReadyPlan::nic_offset(k) )` — нормализованная база без
  смещения шарда/NIC, чтобы `cursor_for_nic` на возобновлении добавил смещение заново ровно один раз; **сырой**
  `min_k my_index[k]` (как в `main.c:1408–1414`, где C затем снова прибавляет смещение на `:269`) задвоил бы смещение и
  сдвинул поток в чужой residue-класс — отличие от C. Завершение скана определяется `position() >= effective_end(k)`,
  а не нормализованной базой. При `shard.of > 1` без явного `--seed`
  печатаем в `stderr` предупреждение о необходимости общего `--seed` (`main-conf.c:3624–3627`). Курсор `ProbeCursor`
  хранит внешний индекс `i` из `transmit_index_stream`, а не счётчик отправленных пакетов — это исключает сдвиг
  `paused.conf` при `shard.of > 1`, `nic_count > 1` и `retries > 0` — отличие от C: индекс адаптера `i >= 8`
  отклоняется с `exit 1` (в C проверка `index >= 65536` переполняет `masscan->nic[8]`, `main-conf.c:2438`).
- **Р3 (`--retries` и граница диапазона):** разблокируем `--retries 0..=999` (`>= 1000` даёт `FAIL: retries=<n>:
  expected number less than 1000`, `exit 1`, `main-conf.c:1936–1954`) и произвольное число раундов BlackRock из конфига.
  В передаче воспроизводим точную формулу `transmit_thread` (`main.c:212–213, 270–273, 328–334, 421–431`):
  `rate = max_rate as u64`, внешний предел `end = min(range, start + resume_count) + retries * range` (без
  `resume-count`: `(retries + 1) * range`), на каждом внешнем `i` внутренний счётчик `r` проходит `retries + 1 ..= 1`,
  вычисляя `x = blackrock_shuffle((i + r * rate) % range)` и увеличивая `i += increment` только после `r == 0` (в C
  удлинение `end` и внутренний цикл `r` складываются мультипликативно в `(retries + 1)^2` проходов по базовому
  диапазону; `scan::transmit_index_stream` уже реализует эту арифметику). В `-sL` сохраняется формула
  `main-listscan.c:35` `end += (retries * max_rate) as u64` с защитой `ScanError::NonTerminating` (спека порта §4(d),
  `crypto-blackrock.c:268–276`) — отличие от C: при заданном `--resume-count` живой скан корректно завершается на
  усечённом `end` (в C `main.c:1425` ждёт `min_index >= range` и зависает), а вырожденный `-sL --retries` завершается
  ошибкой вместо бесконечного цикла.
- **Р4 (фаза ожидания после Ctrl-C и `--wait`):** первое нажатие Ctrl-C печатает в `stderr` строку C
  `waiting several seconds to exit...` + 44 пробела + `\n` (`main.c:1136–1140`), вызывает `handle.pause()` (останавливая
  передачу, но оставляя поток приёма живым), сразу сохраняет `paused.conf` по полученному `CheckpointReady { next_index }`
  (при `next_index < effective_end`) и ждёт `--wait <secs|forever>` (по умолчанию `10`, `forever` = `i32::MAX` с,
  `main-conf.c:3028–3032`, `main.c:1496–1540`), продолжая принимать ответы в `Sink` и обновлять строку статуса
  `waiting N-secs` раз в 250 мс; по окончании ожидания закрывает подвал вывода, печатает `[+] finished: Paused` (либо
  `Completed`, если передача успела закончиться до Ctrl-C) и выходит с кодом `0`. Второе нажатие Ctrl-C немедленно
  завершает процесс с кодом `1` (`_exit(1)` / `ExitProcess(1)`), причём `paused.conf` уже на диске — так сохраняются и
  поздние SYN-ACK, и прогресс — отличия от C: при `--nostatus` обратный отсчёт `--wait` не зависает (в C `main.c:1399,
  1530` декремент `wait` привязан к печати статуса), а итог в логе — `Paused` с целостным подвалом вывода (в C
  принудительный `exit` обрывал подвал, `main.c:1490–1496`).
- **Р5 (`--infinite`):** поддерживаем флаг `--infinite` (`infinite = true` в конфиге, `main-conf.c:2836–2837, 3081`).
  По окончании каждого полного прохода без паузы/отмены поток передачи выполняет `seed = seed.wrapping_add(1)` и
  `repeats = repeats.wrapping_add(1)`, переинициализируя `BlackRock::new(range, seed, rounds)` со стартом
  `(shard.one - 1) * nic_count + nic_index` (`resume_index` и `resume_count` действуют только на первом проходе, следующие проходы идут по всему диапазону
  `[0, range)` плюс ретраи — отличие от C, где метка `main.c:251` стоит до расчёта старта и конца `:269–272` и оба
  параметра переприменяются каждый проход, так что все проходы повторяли бы окно первого), но сохраняет
  `entropy = initial_seed` неизменным, чтобы приёмник продолжал подтверждать SYN-cookie предыдущего прохода
  (`main.c:225–228, 445–449, 545`); выбор источника хэширует `(i.wrapping_add(repeats), x)` (`main.c:379–382`). Строка
  статуса печатает формат C `rate:%6.2f-kpps, syn/s=%.0f ack/s=%.0f tcb-rate=%.0f, 0-tcbs,         \r`
  (`main-status.c:214`) и NDJSON `{"state":"*","rate":{...},"tcb":0,"syn":...}\n` (`main-status.c:56–69`). Выход —
  только по Ctrl-C; `paused.conf` в `--infinite` не создаётся — сознательное отличие от C: в `main.c:1447` нет
  проверки `is_infinite`, C пишет `paused.conf`, если `min_index < count`, но бесконечный скан нечего возобновлять.
  `-sL` вместе с `--infinite` — явный отказ (C зацикливает список, `main-listscan.c:68`).
- **Р6 (диапазоны источника и эфемерный порт по умолчанию):** по умолчанию сохраняем **один** эфемерный порт источника
  `p = 40000 + time % 20000` (`(p, p)`), одновременно поддерживая явные диапазоны ширины `2^k` и для `--source-port A-B`
  (`--adapter-port`), и для `--adapter-ip A-B` (`--source-ip`, `ipv4_mask = B - A`, `main-conf.c:2486–2550`,
  `main.c:378–385`) — в C пара `{p, p+16}` по умолчанию возникает из-за ошибки на единицу `last = port + 16` вместо
  `port + 15` (`main.c:1318` → `port_mask = 0x10` в `main.c:186`), после чего сам C пишет в `paused.conf` строку
  `adapter-port = p-(p+16)` из 17 портов и падает на собственном `--resume paused.conf` (`is_power_of_two(17)` в
  `main-conf.c:2547`); одиночный порт `p` даёт валидный `adapter-port = p` и для `rmasscan`, и для C `masscan`, не
  ломая контракт `autodetect` PR #49 — отличие от C остаётся сознательным; дополнительно `read_paused_conf` при чтении
  чужого C-файла `paused.conf` с `adapter-port = A-B` при `B - A == 16` принимает его с маской `0x10`, чтобы
  `rmasscan --resume` умел подхватывать и `paused.conf`, созданный оригинальным `masscan`.
- **Р7 (`-c`/`--conf` и `-iL`/`--includefile`):** разбираем позиционно в порядке `argv` файлы конфигурации
  `-c <file>` / `--conf <file>` / `--config <file>` (`main-conf.c:2472–2473, 3332–3338, 3868–3924`) с рекурсивными
  директивами `conf = <file>` и `includefile = <file>` (лимит глубины включения 16 против циклов) и файлы целей
  `-iL <file>` / `--includefile <file>` (`main-conf.c:2825–2836, 3375–3377`). Вся работа с ФС живёт в `rmasscan-cli`,
  `rmasscan-core` остаётся чистым — паритет CLI-конвейеров — отличия от C: `/etc/masscan/masscan.conf` автоматически не
  читается (спека порта §4.6), а отсутствие файла или неизвестный ключ завершает процесс с `exit 1`.
- **Р8 (`--pcap` / `--pcap-filename`):** открываем файл захвата до ARP/движка, пишем 24-байтовый заголовок классического
  LE microsecond `.pcap` (`d4 c3 b2 a1 02 00 04 00 00 00 00 00 00 00 00 00 ff ff 00 00 01 00 00 00`, `snaplen = 65535`,
  `linktype = 1` Ethernet) и 16-байтовые заголовки записей `[ts_sec, ts_usec, incl_len, orig_len]` в LE перед кадрами
  (`rawsock-pcapfile.c:669–712, 857–932`). Как в `main.c:829, 935, 943–951`, записываются входящие кадры длиной
  `<= 1514` байт, адресованные нашему диапазону `source_ipv4` и `source_ports`, до проверки SYN-cookie и дедупликации.
  Флаг разрешён только в живом скане (аналогично Р19 форматов) — отличия от C: раннее открытие без лишних кадров при
  ошибке пути и единый потокобезопасный писатель при `nic_count > 1` (в C несинхронизированный `fopen` в каждом
  RX-потоке затирает файл, `main.c:585`).
- **Р9 (`--ttl`, `--badsum`, `--noreset` и TCP-опции):**
  - `--ttl <1..=255>` выставляет `px[offset_ip + 8]` (по умолчанию `255`, `main-conf.c:3003–3009`,
    `templ-pkt.c:1474–1488`); значения `0` и `>= 256` отклоняются с `exit 1` (в C `0` игнорируется, `>= 256` не выходит).
  - `--badsum` (`main-conf.c:2758–2760, 3074`): в C `8e6b3b0` флаг сохраняется в `nmap.badsum`, но нигде не читается
    (мёртвая заглушка); в `rmasscan` инвертируем L4-чексумму на `csum.wrapping_sub(1)` при валидной IPv4-чексумме, чтобы
    пакет проходил маршрутизаторы и отбрасывался целевым TCP-стеком, как задумано.
  - `--noreset` (`main-conf.c:1556–1567, 2382`): принимается и сериализуется в `echo`/`paused.conf` (без собственного
    TCP-стека `rmasscan` и так не отправляет RST).
  - Опции TCP SYN (`templ-tcp-hdr.c:1066–1119`, `main-conf.c:2141–2345`): `--tcp-mss [<u16>|<bool>]` (дефолт: включена,
    `1460`, `[0x02, 0x04, hi, lo]`), `--tcp-sackok [<bool>]` (`[0x04, 0x02]`), `--tcp-wscale [<u8>|<bool>]` (при
    включении без числа — `3`, `[0x03, 0x03, val]`), `--tcp-tsecho [<u32>|<bool>]` (при включении без числа —
    `0x12345678`, `[0x08, 0x0a, ts_be4, 0, 0, 0, 0]`). Опции добавляются в порядке `mss → sackok → wscale → tsecho` и
    выравниваются нулями EOL (`0x00`) до 4 байт с обновлением `ip.total_len`, `tcp.doff` и частичной TCP-суммы —
    отличие от C: в `--tcp-tsecho` исправлены опечатка `templ-tcp-hdr.c:1111–1112` (двойная запись `field[2]`, терявшая
    байт `val >> 24`) и ошибочная граница `num >= 255` в `main-conf.c:2292` (принимается полный `u32`).

## 4. Инварианты совместимости

- **4.1 Индексы при shards, multi-NIC и retries** (`~/masscan/src/main.c:211–228, 258–274, 328–334, 421–431`,
  `crypto-blackrock.c:260–295`): `increment = shard.of * nic_count`, `start = resume_index + (shard.one - 1) * nic_count
  + nic_index`, `end = min(range, start + resume_count) + retries * range`; для каждого `i = start, start + increment,
  ... < end` и `r = retries + 1 ..= 1` выдаётся `x = blackrock_shuffle((i + r * (max_rate as u64)) % range)`.
  *Проверка:* юнит-тесты и proptest в `rmasscan-core` — дизъюнктное объединение всех `shard = 1/Y..Y/Y` (и `nic = 0..K-1`)
  при `retries = 0` в точности равно множеству `0..range` без пропусков и дублей; при `retries = R` мультимножество пар
  `(ip, port)` совпадает с потоком C-оракула (`--offline` / `transmit_index_stream`).
- **4.2 `paused.conf` и `-c`** (`~/masscan/src/main-conf.c:294–416, 2402–2422, 3636–3924`): точный порядок секций
  `masscan_echo`, идемпотентный round-trip `write_paused_conf → read_conf → write_paused_conf`, позиционное перекрытие
  `--resume paused.conf <override-flags>` и принудительный `output-append = true`. *Проверка:* байтовые юнит-тесты
  формата и round-trip для одно- и многоадаптерных конфигов, ключей вывода и TCP-опций + чтение эталонного `paused.conf`
  от C-оракула.
- **4.3 Resume без потерь и дублей** (`~/masscan/src/main.c:269–273, 431, 1408–1414`): `ProbeCursor` фиксирует внешний
  индекс `i` следующего неотправленного шага; конкатенация отправленных зондов прогона 1 (остановленного на произвольном
  `k`) и прогона 2 (`--resume paused.conf`) на любом сочетании `shard`, `retries`, `nic_count` совпадает мультимножеством
  с непрерывным прогоном. *Проверка:* офлайн-тесты на `FakeAdapter` с разрезом посреди пачки повторов.
- **4.4 Фаза ожидания и строка статуса** (`~/masscan/src/main.c:1131–1154, 1447–1540`, `main-status.c:56–125, 210–255`):
  первый Ctrl-C печатает `waiting several seconds to exit...` + 44 пробела + `\n`, сохраняет `paused.conf`, крутит
  обратный отсчёт `waiting N-secs` в течение `wait_secs` секунд (принимая ответы в `Sink`) и закрывает подвал вывода;
  `--infinite` печатает строку `*` / `tcb-rate`. *Проверка:* детерминированные тесты на `ManualClock` + `FakeAdapter`
  (включая `--nostatus --wait 5` и ответы, пришедшие во время `wait`).
- **4.5 Шаблон пакета при `--ttl`, `--badsum` и TCP-опциях** (`~/masscan/src/templ-pkt.c:30–53, 942–1021, 1474–1488`,
  `templ-tcp-hdr.c:1066–1119, 1209–1608`): дефолтный SYN равен 58-байтовому вектору C; добавление/удаление `mss`,
  `sackok`, `wscale`, `tsecho` меняет `ip.total_len`, `tcp.doff` (`(hdr_len / 4) << 4`), паддинг EOL до 4 байт и
  L3/L4-чексуммы; при `--badsum` L3-чексумма валидна (`0xFFFF`), а L4-чексумма гарантированно невалидна. *Проверка:*
  перенос векторов `templ_tcp_selftest` + независимый верификатор RFC 1071.
- **4.6 Захват `--pcap` и контракт `Studio`** (`~/masscan/src/rawsock-pcapfile.c:669–712, 857–932`,
  `studio/crates/studio-protocol/src/lib.rs:147`, `rmasscan-engine/src/identity.rs:67–93`): файл `.pcap` читается
  парсером `rmasscan-lab::pcap` и `tcpdump -r`; `AdapterBinding` сохраняет 6 публичных полей и `job_digest` для
  дефолтных TCP/IPv4 заданий не меняется ни на байт. *Проверка:* юнит-тест дайджеста `identity.rs` и сборка `studio`.

## 5. Как устроено (на уровне швов)

- Генератор индексов, диапазоны источника, опции пакета и сериализация ядровых ключей `ScanConfig` живут в
  `rmasscan-core` (чистая логика без I/O; `ProbeCursor` опирается на внешний индекс `i` и поддерживает бесконечный
  перезапуск прохода для `--infinite`).
- Многопоточный запуск по массиву привязок адаптеров, `pause()` с фазой ожидания, перехват сырых входящих кадров для
  `--pcap` и агрегация `min_index` живут в `rmasscan-engine`.
- Чтение/запись `paused.conf`, рекурсивный разбор `-c`/`-iL`, объединение с ключами вывода, таблица флагов в
  `rmasscan-cli/src/args.rs` и цикл событий `run_live` живут в `rmasscan-cli`.
- `#![forbid(unsafe_code)]` везде, кроме `rmasscan-net`. Новых крейтов нет. Pinned Rust 1.99.1.

- **6.2 Живой паритет (Linux netns на minipc; регрессия Windows VM):**
  - Новый набор `wire-lab.sh --suite scan-control` в изолированном Linux netns (`198.18.0.0/24`):
    1. Шардирование: два прогона `--shard 1/2` и `--shard 2/2` с одним `--seed` в объединении отправляют ровно все SYN
       без пересечений и находят все открытые порты, как одиночный прогон C.
    2. Пауза/продолжение и `--wait`: скан с медленной скоростью прерывается `SIGINT`, ждёт `--wait 2` (принимая ответ,
       отправленный в окно ожидания), сохраняет `paused.conf` и закрывает подвал `-oJ`; следующий запуск
       `--resume paused.conf` досылает ровно оставшиеся цели с `output-append = true`.
    3. Повторы и параметры зонда: `--retries 2` утраивает число зондов на проводе (`(2+1)^2` в пересчёте на диапазон C);

## 8. Отличия от C, которые войдут в README (этап документации)

- **Р1:** нечитаемый файл `--resume` или ошибка записи `paused.conf` завершает процесс с кодом `1`; `paused.conf`
  сохраняется в том числе на хвостовом участке повторов (`range <= min_index < effective_end`).
- **Р2:** индекс адаптера `nic[i]` ограничен `0..=7` с явной ошибкой вместо переполнения буфера `nic[8]` в C.
- **Р3:** скан с `--resume-count` штатно завершается по достижении усечённого предела `end` (в C зависает в ожидании
  `range`), а вырожденный `-sL --retries` отклоняется до входа в бесконечный цикл BlackRock.
- **Р4:** первый Ctrl-C переводит скан в фазу `--wait` с записью `paused.conf` и закрытием подвала вывода (заменяет
  временное ограничение Р18 этапа форматов); `--wait` с `--nostatus` не зависает.
- **Р6:** по умолчанию используется один эфемерный порт `p` вместо забагованной пары `{p, p+16}` C (которая ломала
  собственный `--resume paused.conf` в C), при полной поддержке `--source-port A-B`, `--adapter-ip A-B` и чтения чужих
  C-файлов `paused.conf` с `B - A == 16`.
- **Р7:** `/etc/masscan/masscan.conf` не читается автоматически; ошибки чтения и неизвестные ключи в `-c`/`-iL` фатальны.
- **Р8:** `--pcap` открывается до старта скана, потокобезопасен при нескольких адаптерах и разрешён только для живого скана.
- **Р9:** `--ttl 0` и `>= 256` отклоняются с кодом `1`; `--badsum` реально портит L4-чексумму (в C заглушка); в
  `--tcp-tsecho` исправлены потеря старшего байта и лимит `u32`.
