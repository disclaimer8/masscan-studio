## 1. Итог и границы

**macOS correctness (feth): GO (feth): P1–P3 исправлены (PR #14, влит в main), архив пересчитан исправленным верификатором с неизменёнными вердиктами (`2026-10-25`: [reverify-6968272](2026-10-25-rmasscan-macos-bpf-acceptance-raw/reverify-6968272/README.md), все три каталога без изменений), CI зелёный: проверки PR #14 на `116ec1b` зелёные, прогон main `40232921797` на `baa5cc7` прошёл на macos-14, windows-2022, ubuntu-24.04 и в пакете windows-x64 wire lab. Части A и C PASS, часть B 17 PASS и один INVALID (linkloss, класс отказа линка OPEN до этапа физического NIC; причина: на `feth` у сканера нет события линка при падении линка на стороне пира). Evidence: код `717e45c`, вердикты `2989ace` и повторно `6968272`. (`macos_live` выполнены, узкое повторное ревью серии final-fix одобрено.) Живая приёмка выполнена на запечатанной паре `feth4201`/`feth4202` на одном Mac. Физический NIC (USB/Thunderbolt Ethernet) не
измерялся и в это GO не входит.

**Решение по `linkloss`** (пользователь, 2026-10-25, поправка в плане). INVALID по `linkloss` (сканер завершился `Completed` при падении линка на стороне пира, ни одного скан-стороннего события линка на `feth` нет) **не блокирует** GO для «macOS correctness (feth)». Класс отказа линка переносится как **OPEN** на этап физического NIC. Статус не повышен: это не PASS и не FAIL.

## 4. Топология

Стенд `m1` (запечатан, манифест в `/var/run/rmasscan-lab`, принадлежит root):

- `feth4201` — сторона сканера, MAC `02:ac:00:00:00:01`, без IPv4-адреса, `up`.
- `feth4202` — сторона пира, MAC `02:ac:00:00:00:02`, `198.18.0.2/30`, `up`, `peer feth4201`. Статический ARP на `feth4202`:
  `198.18.0.1 -> 02:ac:00:00:00:01`. Source IP сканера `198.18.0.1` никому не назначен.
- Без uplink, без bridge, без маршрутов наружу, без изменения default route, DNS и pf. Сканируется только `198.18.0.2`.
- Uplink `en0` (интерфейс default route) снимается на каждом прогоне с фильтром лаборатории; результат — **0 кадров лаборатории в
  каждом снятом захвате**: functional-r1 24 из 24, perf-r1 20 из 20, failure-r1 16 из 16 (15 регулярных прогонов и прерванная попытка
  `linkloss`; два прогона прав захвата не имеют по замыслу). Все `uplink.pcap` имеют размер 24 байта (только заголовок). Итого 60
  захватов, 0 кадров. На macOS «received by filter» в tcpdump считает пакеты до фильтра, поэтому критерий — число кадров в
  отфильтрованном pcap.
- Свидетель на стороне пира: `tcpdump` на `feth4202`. Статус стенда (`macos-lab status`) проверяется до и после каждого прогона:
  `raw_run_allowed: true` в каждом `status-pre`/`status-post` (functional-r1 48 из 48, perf-r1 40 из 40, failure-r1 35 из 35; у
  прерванной попытки `linkloss` один `status-link-restored` — `false`, причина в разделе 6).
- Доступ к BPF: на время сессии пользователь выполнил `macos-lab bpf-access --grant` (`/dev/bpf0..15` в `0660 root:staff`), затем
  `--revoke` (`0600 root:wheel`). Два прогона прав (`perm_denied_scan`, `perm_inventory_control`) выполнены после отзыва (`bpf_access:
  denied`). Агенты не вводили пароль и не вызывали `sudo`; все привилегированные действия выполнены пользователем.
- seed 1, rate 100 (часть C: 100, 1000, 10000, 100000), wait 3, retries 0, shard 1/1; NIC=1, TX=1, RX=1.

## 6. Результаты по частям

Счётчики из `verdict.json` (`totals`) проверены чтением и пересчитаны верификатором `2989ace` на скрабленной копии с тем же итогом.

### Часть A: `functional-r1` — overall **PASS**, 29 PASS (FAIL 0, INVALID 0, NOT RUN 0)

24 прогона + 4 группы pause/resume + manifest = 29. Нет rerun, нет discarded, нет прерванных, ни одной отмены pair-quiet.

- Шесть функциональных классов (`c01`–`c06`) и `x01`, каждый два повтора: байты SYN и порядок равны эталону C без нормализации.
- Результаты Open/Closed равны правде с провода без дубликатов; `x01` отклоняет чужие ответы (три вида: незапрошенный порт, неверный
  cookie, неверный порт назначения; по 60 кадров на прогон, `guard_refused` 0; вид «чужой IP» на Mac не пишется, его запрещает защита
  пира, он покрыт запусками Linux/Windows).
- Pause на N=0/1/8/15 (`group_pause_resume_N0/N1/N8/N15`): pause+resume равны непрерывному Rust и эталону C по байтам и порядку, ни один
  probe не потерян и не добавлен на шве.
- `refuse_completed`: завершённое задание не возобновляется, ни одного SYN в проводе.

### Часть C: `perf-r1` — overall **PASS**, 21 PASS (manifest + 20 ячеек)

лаборатории. Класс отказа линка остаётся **OPEN**.

## 7. Хэширование и полнота захвата

Каждый прогон прошёл шлюз raw-run: статус стенда до и после, nonce (`invocation_nonce` сверяется с `run.json`), sha256 каждого
артефакта в `hashes-before-copy.txt`, полный парсинг захвата, чистый выход tcpdump и нулевые потери ядра на свидетеле. Неполный захват —
INVALID, отсутствующий — NOT RUN, повышение до PASS невозможно. Прогоны не отбрасывались (`discarded` пуст во всех трёх каталогах), `--rerun`
не использовался.

Перезапуски по NOT RUN: шлюз «пара тихая» (счётчики интерфейсов не должны двигаться около секунды) отказал до начала любого
действия, rc 2, **9 раз в perf-r1 и 1 раз в failure-r1**; причина — ретрансмиты SYN-ACK от сервисов хоста (кадры одного-трёх пакетов на
`feth4201` в секунде перед ячейкой). Каждый раз набор перезапускался с `--only <оставшиеся теги>`; ничего не отброшено. Одна ранняя
попытка перезапуска была отклонена самим набором из-за ошибки кавычек в `--only` («unknown or unsafe tag», ничего не запущено).

## 9. Ошибки и ограничения

Правила Mac и причины (каждое найдено на живых кадрах):

- **Известный предел верификатора: конец окна полноты.** Окно приёма, в котором ответы обязаны быть результатами, заканчивается на `guest_finished_utc`
  (выход процесса, замеченный опросом раз в 100 мс), а не на исходе сканера. Это может дать только ложный FAIL (поздний ответ внутри окна, но после
  исхода, не попавший в результаты), ложного PASS дать не может; в архиве такого нет. Для остановленных сканов (`stop_silent`, `stop_load`)
  полнота требуется только для ответов не позже чем за 0.25 с до запроса Stop (`wall.outcome − stop_to_outcome_ms`), остальное допускается.
- **Маскирование MAC в Darwin 27.** Процесс, происходящий от ad-hoc-подписанного исполняемого файла без платформенной подписи, видит
  `02:00:00:00:00:00` в `getifaddrs`, `ifconfig` и `arp`. Поэтому MAC стенда берутся из запечатанного манифеста, проверенного как root при
  `up`; не-root `status` принимает точное значение-заполнитель только против манифеста; root не принимает маскирование; заполнитель
  не используется как MAC нигде. Следствие: у `wire_scan` нет кросс-проверки `--src-mac` по ОС (`src_mac_check` = `os-masked`).
- **Syncookies (`net.inet.tcp.syncookie = 1`).** Тихий порт невозможен без sysctl/pf (запрещены), 300 из 300 соединений с backlog 0..2
  завершились. Порты `8099` и `8100-8119` — обычные закрытые; `listeners.json`: `silent: []`, `silent_unavailable: darwin-syncookies`.
  Свойство остановки при пустом пути приёма на macOS — **NOT RUN**, не PASS.
- **Ограничение RST (`rst_rlc`).** Закрытый порт может не получить RST: пропущенный RST не отказ сканера. Верификатор требует, чтобы
  результаты содержали все открытые порты, ничего неизвестного и ни одного дубликата.
- **Wildcard-слушатели хоста 5000 / 7000 / 49158** отвечают на `198.18.0.2`. Правда об открытых портах = listeners лаборатории ∪ LISTEN
  хоста (записывается начиная с `2989ace`); для evidence `717e45c` — SYN-ACK с провода внутри окна при полном захвате, иначе INVALID.
- **RST демонтажа слушателей** после завершения сканера: окно приёма заканчивается на `guest_finished_utc`; расхождения после выхода
  сканера (промежутки 2–97 мс) фиксируются как `post_run_replies`, набор останавливает свидетеля до остановки listeners.
- **Идентичность внедрённых кадров по sha256**, потому что IP id совпадают (RST закрытых портов ядра с id `0xf0e1` — настоящие, 100k
  genuine RST были бы отброшены при сравнении по IP id).
- **Сброс ARP при link down.** Darwin стирает статическую ARP-запись при `ifconfig feth4202 down`; `link --up` восстанавливает её
  (`arp -d` и `arp -S`, проверка постоянной записи) — исправление `097ae8e` внесено ПОСЛЕ живых прогонов (в прогоне 2 `linkloss`
  ARP восстанавливал «официант» пользователя). Живая перепроверка исправления **NOT RUN**.
- **Привязка к 80/443 без root — `EACCES`** (исключение macOS для непривилегированных портов касается wildcard-bind, не привязки к
  адресу). Пир слушает только `8000-8007`; `80` и `443` на Mac закрыты. Следствие: SYN-ACK у `c01` на Mac не проверяется (порт 80
  закрыт, ответ RST).

Ограничения измерения:

- **`bs_drop` — нижняя граница.** Потери ниже BPF (в `feth`, драйвере NIC) им не видны; в спайке подтверждено точное равенство
  `recv − drop − прочитано = 0`, но это счёт BPF-дескриптора.
- **`feth` не физический NIC.** Копирование в ядре; потери ниже BPF, поведение драйвера, нехватка mbuf, пауза драйвера не проверены.
- **Блокировка `write()` — OPEN на любом интерфейсе, включая `feth`.** XNU `bpfwrite` игнорирует `ioflag`, `bpf_movein` выделяет mbuf с
  `MBUF_WAITOK` до драйвера; `O_NONBLOCK` на запись не действует (замечание независимого ревью, ссылки на исходники XNU там). Поэтому
  при нехватке mbuf запись может блокироваться и на `feth`; на физическом NIC к этому добавляется обратное давление драйвера. На
  `feth` без нехватки mbuf блокировок не было (max 70.3 мкс на 206 000 вызовов). Верхней границы дедлайна `send` не доказано. Измерено
  (не ограничено): Stop 2.9–34.5 мс на живом стенде и max 50.5 мс в спайке; «Stop ≤1 с» это результат измерения, не гарантия. Комментарии
  `rmasscan-net/src/lib.rs` и `macos/adapter.rs` исправлены (не утверждают ограниченный неблокирующий `send`; бюджет `recv`/`health` 33 мс).
- **Сон/пробуждение — NOT RUN.**
- **macOS 14 не измерена.** Только 27.0.1; на macOS 14 CI собирает и гоняет offline-тесты (job `macos-14`).
- **Один Mac, одна версия, один стенд.**
- **Класс отказа linkloss — OPEN** (INVALID, раздел 6).
- **Свойство «пустой путь приёма» — NOT RUN** на macOS (syncookies).
- **`macos_live`: 6 из 6 PASS в окне гранта (результаты в разделе 6).** Тесты помечены `#[ignore]` и в CI не идут; до серии final-fix они не запускались, тест полного скана раньше ожидал 80/443 открытыми и падал бы на стенде Mac (исправлен).
- **Граница ≤50 мс на вызов измерена живьём на `feth`, но не доказана как граница.** `macos_live` дал max recv 143 мкс, send 55 мкс, health 85 мкс, idle recv 34087 мкс (≈34.1 мс при `IO_BUDGET` 33 мс). Измерение сделано без нехватки mbuf и не на физическом NIC; при нехватке mbuf `write()` может блокироваться (пункт выше), поэтому доказанной верхней границы нет. Дополняет спайк: превышение `poll` 14.3 мс под нагрузкой, 9.1 мс тихо.
- **Живая перепроверка изменённых путей на итоговом коммите (`c01`, `perm_denied_scan`) — NOT RUN.** Итоговое ревью: не требуется. После
  `717e45c` менялись только `rmasscan-lab` и документы; в серии final-fix `rmasscan-net` получил лишь комментарии, сигнатуру `unsafe fn`
  `ioctl_ptr` и текст `npcap` в примере (поведение не менялось), `engine`/`core` не менялись.
- **Верификатор `3b0f9a2`** (раунд 9: только tcp4-слушатели хоста, неуспех `netstat` не запись, отчёт об открытых ответах
  прогона, мультикаст-страи в жизни сканера, поздние SYN-ACK): итоговое ревью повторно верифицировало им все три каталога на копиях
  с захватами. `macos-verify` на HEAD **воспроизводит каждый закоммиченный вердикт** (functional-r1 PASS 29/29, perf-r1
  PASS 21/21 с gate MET, failure-r1 17 PASS и 1 INVALID `linkloss`); 25 проверок, добавленных раундом 9, все PASS. Вердикты в этом
  отчёте остаются `2989ace` и теперь подтверждены верификатором HEAD.
- **Классификация потери ядра на uplink (M3, оставлено намеренно).** На macOS `bd_dcount` считает только пакеты, прошедшие фильтр
  лаборатории, поэтому `dropped by kernel > 0` на uplink это потерянный кадр лаборатории. Верификатор называет это INVALID (не PASS),
  живой интерлок набора отказывает дальше (`UNPROVEN`), обход безопасности по pcap не срабатывает. Безопасно по отказу (ни PASS, ни
  продолжения), на практике недостижимо (нужны полный store- и hold-буфер совпавших кадров, которые тоже были бы захвачены); в коде
  `macos_verify.rs` стоит комментарий.
- **Текст `npcap` в `run.json` на macOS (M7).** Закоммиченное evidence хранит старый текст `"npcap":{"unavailable":"raw packet I/O is
  not implemented on this platform"}` (он вводил в заблуждение: сырой ввод-вывод на macOS есть). `wire_scan` после final-fix пишет
  вне Windows «not applicable: Npcap is Windows-only …». Ни один верификатор не зависит от этой строки (проверено поиском по
  `rmasscan-lab`); evidence не менялось.
- **Вердикты `capture marker` / `capture responder` на macOS (I3).** Обе подкоманды отказывают с rc 2 и объяснением (раньше `marker` мог
  писать кадры на любом интерфейсе без защиты лаборатории); набор macOS ими не пользуется; Linux и Windows без изменений.
- **Обход безопасности по каталогам (M4).** Любой `*.gz` в каталоге прогона (kept, discarded, aborted, `.work`) закрывается отказом
  безопасности «compressed capture is not allowed; store captures uncompressed»: верификатор не распаковывает.
- **`unsafe` вне `sys`/`ifinfo`/`process` (M2).** Только тестовый `macos/spike.rs` (`cfg(all(macos, test))`, нет в продуктовой сборке); он
  использует `kevent`/`kqueue`, которых нет в `sys`, поэтому перенос добавил бы в продукт неиспользуемый `unsafe`. Причина записана в
  заголовке модуля; `ioctl_ptr` стал `unsafe fn` с разделом `# Safety` и своим SAFETY-комментарием на каждом месте вызова (M1).
- Закрыто в серии final-fix, только лаборатория и без живой проверки: R5-1 задачи 2 (`link` требует запечатанный стенд и `feth4202` в
  `created`), `link --up` восстанавливает ARP только при отсутствующей или неполной записи (полная чужая запись не перезаписывается,
  rc 10), шаг `arp` стал именованной константой. Открытые замечания: три
  дефекта предыдущего независимого ревью `2026-10-25-7ffa155` (потеря SSH-сеанса lock Windows, чужие незавершённые захваты Windows,
  Linux Stop capture) лежат вне 2C и в очереди.
- Python в репозитории и скриптах не использован.

## 11. Перепроверка после исправлений

Живая перепроверка изменённых путей на итоговом коммите **NOT RUN** (раздел 9; итоговое ревью признало её ненужной); этой записи в evidence нет.

**Живые тесты адаптера** (`macos_live`, выполнены в окне гранта, результаты в разделе 6). Процедура окна (стенд поднят, доступ к BPF выдан,
запуск без root; `$REPO`, `$TARGET` (свой приватный `CARGO_TARGET_DIR`), `$SCRATCH` и `$OUT` (существующий каталог для файлов) подставляются
оператором; `$LAB` это `rmasscan-lab` из той же ревизии, `$BIN` путь тестового бинарника):

```sh
cd "$REPO/rmasscan" && CARGO_TARGET_DIR="$TARGET" cargo test --locked -p rmasscan-net --test macos_live --no-run   # BIN = напечатанный путь .../deps/macos_live-<hash>
FILTER='ether host 02:ac:00:00:00:01 or ether host 02:ac:00:00:00:02 or ether host 02:ac:00:00:00:11 or net 198.18.0.0/30'
# ворота (остановиться на первом провале, ничего не запускать):
"$LAB" macos-lab status --run-id m1 > "$OUT/status-pre.json"       # raw_run_allowed true, bpf_access granted
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate > "$OUT/alf.txt"   # Firewall is disabled. (State = 0)
/usr/sbin/lsof -nP -iTCP@198.18.0.2 -sTCP:LISTEN > "$OUT/leftover-listeners.txt"    # пусто
/bin/ps -axo pid,command | grep -E 'wire_scan|tcpdump .*feth420|peer listen|capture dump' | grep -v grep > "$OUT/leftover-procs.txt"   # пусто
# свидетель на uplink на всё окно, затем тесты:
/usr/sbin/tcpdump -p -n -i en0 -w "$OUT/uplink.pcap" "$FILTER" 2> "$OUT/uplink.err" &  TD=$!
sleep 2; kill -0 $TD
RMASSCAN_BPF_LAB_MANIFEST=/var/run/rmasscan-lab/m1.json RMASSCAN_BPF_OUT_DIR="$OUT" "$BIN" --ignored --test-threads=1 > "$OUT/test.log" 2>&1
sleep 1; kill -INT $TD; wait $TD                                    # rc 0
"$LAB" macos-lab status --run-id m1 > "$OUT/status-post.json"      # raw_run_allowed true
/usr/sbin/tcpdump -n -r "$OUT/uplink.pcap" 2>/dev/null | wc -l     # 0
```

Эквивалент без скрипта окна: `cargo test --locked -p rmasscan-net --test macos_live -- --ignored --test-threads=1` с теми же двумя переменными окружения. После окна: `bpf-access --revoke` и `down` (выполнил пользователь).

Ту же команду описывает операторская документация `rmasscan/docs/macos-feth-lab.md` (раздел «Live adapter tests»). Перепроверка исправлений
ревью по поведению (красный-зелёный тесты, мутации верификатора, повторная верификация вердиктов на копиях) проведена ревьюером
