# rmasscan: баннеры, подэтап 4c (TLS и X.509), приёмка (итоговый отчёт подэтапа)

Дата: 2026-11-16. Ветка `feat/rmasscan-banners-4c`, база `fab13114` (слияние 4b, PR #62). Документ фиксирует
измеренное и открытое. Статусы: PASS / FAIL / INVALID / NOT RUN / OPEN, никогда не повышаются.
Спека: [design](../superpowers/specs/2026-11-13-rmasscan-banners-design.md) (Р1–Р17; изменения по итогам 4c — §12).
План: [plan](../superpowers/plans/2026-11-13-rmasscan-banners-4c.md), задачи П и 0–14.

## 1. Итог и границы

- Парсеры и стек подэтапа приняты на эталонах оракула и дифференциалах против C `8e6b3b0`: 32 кейса X.509
  (вся подача целиком/по байту/8 нарезок), 39 кейсов TLS-записей (записи и действия), 240 мутированных DER без
  расхождений, пять ClientHello побайтно (дамп оракула, сборки default и ASan одинаковы), `--readscan` входа с
  TLS-записями против собранного из пина C во всех форматах и `certs` — байт в байт. Живой путь закрыт тестами
  FakeAdapter IPv4 и IPv6 (второе соединение, STARTTLS, heartbleed, сброс в конце `--wait`, все форматы).
- Главные находки сверки (справка §G, §F): обычные ClientHello статичны (динамизация только в режимах); SAN у C
  не подавляется номером сертификата в цепочке (гейт `count` только для CN); ошибка `ASN1_push` и порядок
  записей `ssl`/`X509*` у C зависят от нарезки (E2.9, E2.10) — приведены к эталону целого потока по Р13; хвост
  STARTTLS разбирает TLS-парсер (E2.8′ вместо E2.8); зонд heartbleed на первом соединении на провод не уходит
  ни у C, ни здесь (FIN_WAIT, И24); список сертификатов короче первого сертификата зависает у C — исправление
  E1.3 (фаззинг нашёл зависание сначала у нас, оракул подтвердил у C).
- Живые окна стендов в этой сессии **NOT RUN** (раздел 6): окно Linux (`t10_tls4`, `t11_tls6`, `t12_heartbleed` и
  регрессии), Windows VM и macOS `feth` требуют стендов и root/sudo, которых у исполнителя здесь нет. Кейсы,
  сценарии и верификатор готовы и приняты юнит-тестами на собственном стеке продукта; живые прогоны — за
  контролёром на стендах.
- Фаззинг: семейства `tls` и `x509` добавлены (15 семейств); короткий режим в юнит-тестах и timed-прогоны 120 с
новых семейств без находок (раздел 5). Часовые прогоны и полный повтор 13 прежних — NOT RUN; 24 ч — критерий 4d.

## 3. Эталоны оракула и дифференциалы

- Задача 0: справка TLS сверена с исходниками C пина `8e6b3b0` построчно; 10 поправок к справке TLS/SMB (§G).
- Оракул: копия обвязки 4b вне репозитория (Р14), режимы `tls-hellos`, `x509`, `x509-vectors`, `tls`;
  сборки default и ASan дают одинаковые дампы; провенанс в манифестах эталонов.
- ClientHello: 8 строк дампа (5 шаблонов и 3 динамизированных hello при фиксированном `time()`) побайтно.
- X.509: 32 кейса (векторы `proto-ssl-test.c`, цепочки case1/case3, ручные DER, мутации google) во всех нарезках;
  отдельный дифференциал на 240 мутированных DER — 0 расхождений с целым прогоном C.
- TLS-записи: 39 кейсов (потоки case1/2/3 и синтетические записи alert/heartbeat/cert) — записи и действия во
  всех нарезках; кейс зависания C (E1.3) эталоном не является и закреплён юнит-тестом.
- `--readscan`: вход `-oB` с TLS-записями (ssl, X509, две X509CA, vuln, захват heartbleed, нагрузка у предела
  писателя 16 360 байт, запись IPv6): собранный из пина C и rmasscan дают одинаковые `-oL`/`-oJ`/`-oD`/`-oX`/`-oG`/`-oH`/`-oU`,
  `certs` (stdout и файл) и вывод по умолчанию (скрипт дифференциала вне репозитория; коммит-тесты закрепляют
  `-oL` и PEM-обёртку `certs`).

## 4. Тесты и гейты

- `rmasscan-proto`, `rmasscan-core`, `rmasscan-engine`, `rmasscan-net`, `rmasscan-cli`: все тесты зелёные на Mac,
  кроме восьми заранее известных падений окружения в `detect_readonly` (песочница сети; те же на чистой базе
  `fab13114`).
- `rmasscan-lab`: зелёные, кроме падений окружения с `PermissionDenied` (сокеты и группы процессов в песочнице;
  подтверждены на чистой базе для capture и qmp).
- clippy `-D warnings` и `cargo fmt --check` по воркспейсу: 0. Studio: `cargo check --locked` зелёный; тесты
  зелёные, кроме обоих тестов `studio-runner/tests/socket_session.rs`, которые падают в этой песочнице точно
  так же на чистой базе `fab13114` (сверено поименно; OPEN, раздел 6); `cargo xtask test` останавливается на
  них же. Дерево `studio/` веткой не тронуто.
- Новых внешних крейтов нет; `Cargo.lock` воркспейса rmasscan не менялся с базы (проверка приёмки).

## 5. Фаззинг

Новые семейства `tls` и `x509` (15 семейств; короткий режим в юнит-тестах зелёный). Прогоны этой сессии
(debug-сборка, Mac; отчёт x509 — `2026-11-13-rmasscan-banners-4c-raw/fuzz-tcp-r1/x509.json`, для tls сохранена
консольная строка прогона: файл отчёта двух попыток регенерации не дошёл до диска в этой песочнице, третья
попытка не уложилась в отведённый ей таймаут при загруженной машине — цифры ниже из завершённого первого прогона):

| Семейство | Прогон | Входов | Падения | >100 мс | Нарушения инвариантов | Расхождения нарезки |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| tls | `--duration 120s --seed 20261115`, корпус `tcp-banners` | 1 243 590 | 0 | 0 | 0 | 0 |
| x509 | `--duration 120s --seed 20261115`, корпус `x509` | 222 482 | 0 | 0 | 0 | 0 |
| framework | `--count 3000 --seed 20261115` | 3 000 | 0 | 0 | 0 | 0 |
| stack | `--count 2000 --seed 20261115` | 2 000 | 0 | 0 | 0 | 0 |

Коды выхода timed- и счётных прогонов x509/framework/stack — 2 (`MEMORY NOT MEASURED`: в этой песочнице нет
замеров RSS; находок нет), tls — 0 (`CLEAN`). Находка фаззинга до фикса: зависание на списке сертификатов
короче сертификата — есть и у C, исправление E1.3 закреплено юнит-тестом (раздел 3). Часовые прогоны новых
семейств и полный повтор 13 семейств 4b на стенде — **NOT RUN** (раздел 6); 24 ч — критерий 4d.

## 6. NOT RUN и OPEN

- **NOT RUN:** живые окна Linux (`t10_tls4`, `t11_tls6`, `t12_heartbleed`, регрессии прежних окон), Windows VM,
  macOS `feth`, физические NIC. Причины: нет стендов и root в этой сессии. Кейсы, сценарии, верификатор и
  responder готовы; команды — `wire-lab.sh --suite banners` на хосте стенда Linux (окно 4b команда) и сюиты
  Windows/macOS по их разделам rust-lab.md, вердикт — `banners-verify`.
- **OPEN:** оба теста `studio-runner/tests/socket_session.rs` падают в этой песочнице и на чистой базе
  (к 4c отношения не имеет — Studio не менялась); решение за контролёром.
- **OPEN (И19 4b):** повторять ли дедуп-странность C — без изменений, ждёт пользователя.
