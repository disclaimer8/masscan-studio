# rmasscan: управление сканом — план реализации (КАРКАС, заполняет Denys)

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ САБ-СКИЛЛ — superpowers:subagent-driven-development.
> Шаги в чекбоксах (`- [ ]`). Каркас сгенерирован Claude: структура, границы задач, карта файлов и скелеты
> TDD-шагов на месте; строки **ЗАПОЛНИТЬ:** (ссылки `~/masscan/src` файл:строка, байты, формулы, значения тестов)
> вписывает Denys. Пока они не заполнены, план не исполняется.

**Goal:** поведенческий паритет rmasscan с masscan по управлению сканом (retries, shards, pause/resume, wait-фаза,
infinite и смежные флаги).

**Architecture:** генератор индексов и shards/retries — чистая логика в `rmasscan-core`; пауза/resume — состояние
`rmasscan-engine` + сериализация в `rmasscan-cli`; флаги — `args.rs`→`core::config`.

**Tech Stack:** Rust 1.99.1, Cargo workspace `rmasscan/`, без новых крейтов.

**Spec:** `docs/superpowers/specs/2026-11-08-rmasscan-scan-control-design.md`

## Global Constraints

- `#![forbid(unsafe_code)]` во всех крейтах, кроме `rmasscan-net`.
- Ноль новых зависимостей; `Cargo.lock`/`deny.toml` без изменений; дерево только Rust/docs (language-guard зелёный).
- Ноль живого трафика/открытия NIC в тестах — только фейки/офлайн.
- Приватность публичного репо: ни имён хостов/учёток, ни домашних путей, ни LAN-адресов в коде/тестах/комментах.
- Сборки и тесты — на ноутбуке (Linux), **но Windows/macOS clippy+тесты проверяет только GitHub CI** (Linux-гейт
  ноутбука их не ловит — см. историю этапа форматов).
- TDD: сперва красный тест, затем минимальная реализация со ссылкой на C файл:строка в комментарии и коммите.

## Review Focus

> Пять входов/режимов отказа, которые спека подразумевает, но ни один тест задачи не покрывает — most likely first.
- ЗАПОЛНИТЬ (например: shard X/Y при Y=1; resume из `paused.conf` с изменённым списком целей; retries при пустом
  диапазоне; Ctrl-C во время wait-фазы; `-c` с конфликтующими ключами). Для каждого — тест в задаче-владельце.
