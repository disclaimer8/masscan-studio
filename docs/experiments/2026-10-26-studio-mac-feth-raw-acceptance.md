## 4. Топология и действия пользователя

Стенд `m1`: `feth4201` (сканер, `02:ac:00:00:00:01`, без IPv4) <-> `feth4202` (пир, `02:ac:00:00:00:02`, `198.18.0.2/30`), манифест
`/var/run/rmasscan-lab/m1.json`. Свидетели: в окнах `05ab27f` `tcpdump -p -n -U -s 0 -i feth4202 -w peer.pcap` без фильтра; в окнах финальной ветки с фильтром
`not (ether src 02:ac:00:00:00:02 and udp port 5353)` (§9: отклонение от плана ради приватности: собственный mDNS хоста с именами). Uplink:
`tcpdump -p -n -U -s 0 -i en0 -w uplink.pcap '<фильтр лаборатории>'` (uplink `en0`, шлюз `192.168.1.1`, маршрут по умолчанию не менялся).
Пир слушает `8000-8007`; `alf.txt` = `Firewall is disabled. (State = 0)`; процессов-остатков нет. **Слушатели хоста не записаны**: `host-listen-before.txt` и `host-listen-after.txt` в окнах `05ab27f` содержат только `rc 0`; в финальном окне они содержат `rc 0` и строку «not recorded: macOS hides the TCP table from processes started by ad-hoc-signed tools» (§9) (netstat вышел с кодом 0 без единой строки, причина не сохранена), а `lsof` от пользователя дал пустой вывод (rc не записан; шлюз принимал rc 0 или 1 при пустом выводе, а такой `lsof` видит только сокеты пользователя и мог быть слеп без сообщения). Поэтому утверждения «на хосте нет слушателей `198.18.0.2`» отчёт не делает; wildcard (`*`) слушатели хоста (AirPlay на 5000 и 7000 и т. п.) могли отвечать на `198.18.0.2`. Причина теперь известна и записана (§9.15): macOS 27 прячет таблицу TCP от потомков ad-hoc-подписанных программ. Открытое множество кейса `s1_full` в окнах `05ab27f` выведено из SYN-ACK на проводе при полном захвате пира (1046 из 1046, drop 0): `8000-8007`; в финальном окне 1038 кадров из 1038, drop 0.
Задание Studio: `targets 198.18.0.2`, source `198.18.0.1`/`02:ac:00:00:00:01`, next hop `02:ac:00:00:00:02`, source port 40000, wait 3 с, retries 0.

## 9. Ошибки и ограничения

1. **Грант BPF на окно.** Пока действует грант (в прежнем цикле от B до F около 23 минут; в финальном цикле стенд и грант простояли около 02:15 до 07:56, через сон Mac), `/dev/bpf*` открыты для группы `staff`: любой
   процесс staff на этом Mac мог бы открыть BPF и писать в любой интерфейс. Грант нужен независимым свидетелям `tcpdump`, не root-runner.
   Защита этим этапом не доказывается; доказательство изоляции это uplink-захват (0 кадров). После `down` права `0600 root:wheel` (§4).
2. **`feth` не физический NIC.** Пара копирует кадры в ядре; поведение USB/Thunderbolt Ethernet, блокировки `write()` и потерь ниже BPF
   не проверено. **NOT RUN**.
3. **Один Mac и одна версия macOS** (27.0.1, arm64, M-серия); другие версии, macOS 14 в частности, живьём **NOT RUN** (CI на macos-14
   гоняет только офлайн-тесты).
4. **Resume после перезапуска Studio на raw: NOT RUN** (действие E не делалось). Путь доказан на Simulation, а raw-дельта (повторное
   открытие адаптера на Resume) покрыта `s2_pause` внутри одной сессии; дефект именно в связке «новая сессия + сохранённый checkpoint»
   остаётся **OPEN**.
5. **Sleep/wake и VPN: NOT RUN.**
6. **Диалог Authorize может остаться незамеченным все 180 с**: из 6 показанных диалогов этапа 3 остались без ответа (`05ab27f` 20:27:13 → 20:30:13, `50d717e` 02:27:06 → 02:30:06,

   ловятся (приёмка engine отдельно). **OPEN**.
9. **Формулировки `studio-verify` (код не менялся, замечание на потом).** При отсутствующем Start сообщение «the Start action of the case is in the
